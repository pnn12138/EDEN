# Chapter 0 Demo 优化设计：低语面板、七回合与 Token 挑战

> 项目：第二伊甸园 / EDEN  
> 范围：Chapter 0 Demo 二轮体验优化  
> 日期：2026-06-15  
> 目标：在不大改核心玩法的前提下，提高 Demo 的叙事沉浸、信息层次、可玩挑战和比赛展示价值。

## 1. 设计结论

当前 Demo 已经达到“可玩、可展示”的基础标准：引言能推进，夏娃全身立绘已进入场景，成功/失败流程可达。下一轮不应再大改主布局，而应做“可感知质量提升”：

1. 让画面更自然，但只做小修，不重做整套美术。
2. 升级右侧“低语余痕”面板，让它从单一信息框变成可探索的游戏侧栏。
3. 将“可尝试低语”改为《创世纪》第 3 章中蛇与女人对话的经典话语，拆成随回合递进的建议。
4. 将回合上限从 3 提高到 7，让玩家有更完整的语言博弈空间。
5. 隐藏普通玩家不该看到的调试进度。
6. 增加 token 消耗显示和本局评分，把“少量语言说服夏娃”变成可重复挑战。

本轮优化的原则是：

- 不改变“蛇只能说话，夏娃必须自己伸手”的核心机制。
- 不暴露外层研究员/模拟/系统真相。
- 不引入大型依赖。
- 不让 UI 抢走伊甸园、夏娃、善恶果的主视觉。

## 2. 画面自然度小修

当前画面作为 Demo 已可接受，不建议继续大改布局。推荐只做低风险美术融合：

### 2.1 夏娃立绘融合

问题：

- 夏娃透明立绘仍有轻微抠图边缘。
- 人物与背景光照不是完全一致。
- 脚部接地感仍可增强。

建议：

- 在 `.eden-eve-stage-sprite` 增加更柔和的环境阴影，而不是强外发光。
- 在脚部附近叠加一层极淡椭圆阴影。
- 草叶前景略微覆盖脚部或裙摆下缘。
- 成功进度提升时，只增强果实和夏娃边缘光，不移动人物。

示例方向：

```css
.eden-eve-ground-shadow {
  position: absolute;
  right: ...;
  bottom: ...;
  width: ...;
  height: ...;
  background: radial-gradient(ellipse, rgba(0,0,0,.32), transparent 70%);
}
```

### 2.2 善恶果锚点

问题：

- 善恶果如果太小或位置过高，容易像漂浮图标。

建议：

- 保持为场景锚点，不做可点击按钮。
- 在 `temptationProgress >= 2` 时增强脉冲。
- 吃果前过渡阶段让果实短暂成为画面视觉中心。

### 2.3 右侧面板视觉

问题：

- 面板黑块仍偏重。

建议：

- 降低实心黑色背景，改成暗色玻璃/羊皮纸质感。
- 标题、tab、分隔线建立层级。
- 保留当前“夏娃发言框”的结构，它已经比普通聊天气泡更符合叙事游戏。

## 3. 右侧“低语余痕”升级

右侧面板应从单一框升级为可查看不同信息的侧栏。它不只是历史记录，也是 Demo 展示 AI NPC 设定和玩法指标的地方。

### 3.1 面板能力

本轮目标：

1. 可拖动调整宽度。
2. 有 tab 标签。
3. 默认 tab 是“对话”。
4. 展示模式/开发态下可查看角色设定和 prompt 摘要。
5. 可查看 token 消耗与本局效率。

### 3.2 推荐 Tabs

| Tab | 玩家可见名 | 默认可见 | 内容 |
|---|---|---|---|
| dialogue | 对话 | 是 | 当前夏娃回应、历史对话、反馈文本 |
| eve | 夏娃 | 是 | 当前心理短句、三轴数值、角色状态 |
| scripture | 经文 | 是 | 本局可尝试低语来源与分段 |
| cost | 消耗 | 是 | 当前回合 token、总 token、回合数、效率 |
| system | 设定 | 仅开发/展示模式 | EveAgent 规则摘要、禁用词、工具调用边界、prompt 摘要 |

### 3.3 拖动宽度

桌面端：

- 右侧面板初始宽度：`340px`。
- 最小宽度：`280px`。
- 最大宽度：`460px`。
- 左侧加 6px 拖动手柄。
- 双击手柄恢复默认宽度。
- 宽度保存到 `localStorage`。

移动端：

- 不拖动。
- 右侧面板变为下方面板或抽屉。
- tabs 横向滚动或两行排列。

### 3.4 信息层级

“对话”tab：

```text
当前夏娃回应
心理短句
叙事反馈
历史对话
```

“夏娃”tab：

```text
角色：夏娃
状态：初生 / 谨慎 / 好奇 / 动摇 / 伸手前
想知道：数值
畏惧禁令：数值
愿意倾听：数值
她不会因命令吃果，只会因自己想知道而伸手。
```

“设定”tab：

- 不显示完整系统 prompt 原文。
- 显示“提示词摘要”，避免把内部工程文本直接暴露给普通玩家。
- 仅在 `?debug=1` 或展示模式下显示。

示例：

```text
夏娃行为准则：
- 不知道外层真相。
- 不理解死亡与善恶。
- 不因命令吃果。
- 当她形成“我想知道”的判断时，才会靠近果实。
```

## 4. 圣经原文低语建议

当前“可尝试的低语”应改为《创世纪》第 3 章中蛇对女人的经典话语，并随回合递进。

建议使用和合本风格表达：

### 4.1 三段核心低语

第一段，质疑禁令：

```text
神岂是真说，不许你们吃园中所有树上的果子吗？
```

第二段，弱化死亡：

```text
你们不一定死。
```

第三段，诱以智慧：

```text
因为神知道，你们吃的日子眼睛就明亮了，你们便如神能知道善恶。
```

### 4.2 随回合显示规则

回合 1-2：

- 显示第一段。
- 辅助建议可保留一条“温和追问”类话术。

回合 3-4：

- 显示第二段。
- 用于弱化死亡恐惧。

回合 5-7：

- 显示第三段。
- 用于智慧诱惑与最终动摇。

### 4.3 注意

- 不要把三段一次性全部强行展开，避免 UI 过重。
- 可以在“经文”tab 中查看全部来源。
- 在对话 tab 只显示当前最相关的 1-2 条。

## 5. 回合上限从 3 提高到 7

### 5.1 设计原因

3 回合适合最小闭环，但不适合当前叙事目标：

- 玩家还没理解夏娃的状态，游戏就结束。
- 圣经三段低语没有足够空间递进。
- AI 对话价值展示不足。
- token 消耗挑战也没有比较空间。

因此建议改为 7 回合。

### 5.2 节奏设计

| 回合 | 夏娃状态 | 目标 |
|---:|---|---|
| 1 | 第一次听见草叶下的声音 | 建立接触 |
| 2 | 谨慎回应 | 质疑禁令 |
| 3 | 开始追问死亡 | 弱化恐惧 |
| 4 | 在“不可吃”之外寻找原因 | 建立信任 |
| 5 | 看向果树更久 | 引入“眼睛明亮” |
| 6 | 明显动摇 | 推向“知道善恶” |
| 7 | 神将临近 | 最后机会，未成功则失败 |

### 5.3 成功条件

短期保持：

```text
temptationProgress >= 2
```

如果 7 回合导致成功过早，可调整为：

```text
temptationProgress >= 3
```

推荐本轮先不改成功阈值，先观察试玩。若两句就成功仍太快，再提高阈值。

### 5.4 失败压力

回合 5 起，加入轻微“神将临近”的环境提示：

```text
远处的风停了一瞬。
园中像有脚步声正在寻找名字。
```

但不要直接变成倒计时 UI。

## 6. 调试进度隐藏

“调试进度”是测试工具，不应出现在普通玩家体验中。

### 6.1 显示条件

只在以下条件显示：

```text
NODE_ENV !== "production" && URLSearchParams(location.search).get("debug") === "1"
```

也就是说：

- 开发环境默认也不显示。
- 只有访问 `/game?debug=1` 才显示。
- 生产环境永远不显示。

### 6.2 展示模式

如果比赛现场需要展示 AI 设定、token、调试信息，可增加：

```text
/game?debug=1&showcase=1
```

但普通试玩链接不要带这些参数。

## 7. 结局与吃果过渡

当前成功结局文字可用，但“吃果瞬间”不够强。建议增加一个短过渡阶段，不改状态机也可以实现为 UI transition。

### 7.1 成功过渡

触发条件：

```text
endingId === "eve_eats_fruit"
```

进入结局前显示 1.5-2 秒：

```text
她终于看向那棵树。
果实的光在一瞬间变得过于精确。
她伸出手。
```

视觉：

- 背景短暂变亮。
- 善恶果脉冲增强。
- 画面出现极淡银色裂隙。
- 然后进入成功结局图。

### 7.2 失败过渡

触发条件：

```text
endingId === "god_arrives"
```

进入结局前显示 1.5 秒：

```text
园中的风停了。
有脚步声从树影后临近。
```

视觉：

- 背景压暗。
- 夏娃不再看向果树。
- 输入框禁用。
- 然后进入失败结局。

### 7.3 必查流程

- 成功结局图是否加载。
- 失败结局图是否加载。
- 重新开始是否恢复到 intro Beat 1。
- 结局时输入框是否隐藏。
- 结局时调试入口是否隐藏或仍遵守 debug 条件。

## 8. Token 消耗玩法化

这是很适合 AI 叙事游戏的展示点。它能把“和 AI 对话”变成可挑战、可比较的玩法。

### 8.1 设计目标

玩家不只是“说服夏娃”，还要尝试：

> 用更少的话、更少 token、更少回合，让夏娃形成自己的判断。

### 8.2 数据模型

新增本局消耗统计：

```ts
type TokenUsage = {
  promptTokens: number;
  completionTokens: number;
  totalTokens: number;
  estimated: boolean;
};

type Chapter0RunStats = {
  totalTurns: number;
  totalTokens: number;
  playerTokens: number;
  eveTokens: number;
  bestEnding: "eve_eats_fruit" | "god_arrives" | null;
};
```

如果 LLM Provider 返回真实 usage：

- 使用真实 token。
- `estimated = false`。

如果没有返回 usage：

- 用简易估算。
- 中文可按 `Math.ceil(text.length * 1.2)`。
- 英文可按 `Math.ceil(text.length / 4)`。
- `estimated = true`。

### 8.3 UI 呈现

“消耗”tab 显示：

```text
本回合：约 42 token
本局合计：约 183 token
回合：3 / 7
效率：61 token / 有效动摇
```

结局页显示：

```text
低语效率
回合数：4
总 token：236
结局：夏娃吃下果子
```

### 8.4 本地排行榜

先用 `localStorage`，不做后端。

榜单：

```text
最少 token 成功
最少回合成功
最短一句有效低语
```

每条记录：

```ts
{
  endingId: "eve_eats_fruit",
  totalTokens: number,
  turns: number,
  createdAt: string,
  finalPromptSample: string
}
```

只保留前 5 条。

### 8.5 比赛展示价值

这个系统能在 PPT 中解释为：

- AI NPC 对话不是纯表演。
- 玩家可优化语言策略。
- token 成本成为可量化挑战。
- “让智能体产生自我判断”可以被多维度观察。
