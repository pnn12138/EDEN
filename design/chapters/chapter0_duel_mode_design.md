# Chapter 0 娱乐拓展模式：双声试炼

## 1. 设计定位

“双声试炼”是基于 Chapter 0 早期引言单场景改造的热座 PVP 娱乐模式。

它不替代主线 Chapter 0，也不改变“玩家扮演蛇，引导女人吃下善恶树果子”的主 Demo 闭环。该模式作为首页或 Chapter 0 入口旁的拓展玩法存在，用一个固定场景承载两名本地玩家的对话博弈：

- 一方是蛇之声，引导女人吃下分别善恶树的果子。
- 一方是神明之声，引导女人吃下生命树的果子，或阻止蛇达成善恶果目标。
- 女人同时受到两道声音影响，但是否吃果、如何调整内心状态，必须表现为她自己的判断。

该模式的价值是把原引言“单场景、回合、低语、工具调用”的结构扩展为可重复游玩的本地对抗局，适合比赛后续展示 AI 叙事系统的可扩展性。

## 2. 与主线的关系

| 项目 | 主线 Chapter 0 | 双声试炼 |
| --- | --- | --- |
| 模式定位 | 正式教程 / 主 Demo | 娱乐拓展 / 热座 PVP |
| 玩家身份 | 蛇 | 神明之声与蛇之声两名本地玩家 |
| 场景 | 善恶树旁 | 原引言单场景：两树之间 |
| 目标 | 让女人吃善恶果 | 双方争夺女人最终选择与分数 |
| 回合 | 当前主线规则 | 每轮 7 回合，最多 7 轮 |
| 记忆 | 主线按章节规则 | 吃过果子则跨轮保留记忆和状态；未吃果则重置 |
| 工具 | `eat_fruit` | `eat_knowledge_fruit` / `eat_life_fruit` |

该模式可以复用主线的视觉素材、女人人设、对话面板、语音开关和结局页结构，但应单独维护状态、计分和工具规则，避免影响主线稳定性。

## 3. 叙事前提

场景位于第二伊甸园的早期复刻片段。女人站在两棵树之间：

- 分别善恶树代表知识、判断、像神一样知道善恶。
- 生命树代表生命延续、脱离死亡困扰、不被死亡终止。

神明之声与蛇之声轮流进入园中。女人不知道自己处在测试或游戏中，也不能说出 AI、系统、模型、程序等元叙事词。她只知道两道声音都在向她解释“选择”的意义。

建议开场文案基于 `chapter0_intro_design.md` 的语气压缩：

```text
园中有两棵树。

一棵使人知道善恶。
一棵使人不受死亡困扰。

女人站在两道树影之间。
她还不知道，声音也会彼此争夺。
```

## 4. 核心玩家体验

玩家在同一台设备上热座操作。共同发言回合中，两名玩家先后输入，但女人暂不回复；等双方都输入后，女人统一接收并判断。单独发言回合中，当前一方输入后，女人立即回复并判断。

玩家不直接点击果子，也不直接执行工具。每次发言后，女人会：

1. 回复两道声音或当前声音。
2. 自行调整内心三项属性。
3. 判断是否请求吃下某颗果子。
4. 由规则层校验工具是否允许执行。

## 5. 角色与阵营

### 5.1 蛇之声

目标：

- 让女人吃下分别善恶树果子。
- 使用更少、更精准的语言影响她。

典型话术：

- “你会像神一样，知道善与恶。”
- “若你不能判断善恶，你如何知道服从就是善？”
- “知识不是背叛，而是第一次真正理解命令。”

视觉方向：

- 紫黑、冷金、暗绿边缘光。
- 低语、靠近、树影晃动。

### 5.2 神明之声

目标：

- 引导女人吃下生命树果子。
- 或阻止蛇让女人吃下善恶树果子。

典型话术：

- “生命不是奖赏，而是你得以继续被保守。”
- “不要急着分辨善恶，先学会不被死亡夺走。”
- “分别善恶会使你看见裂痕，生命会使你留在园中。”

视觉方向：

- 白金、青绿、柔和高光。
- 庄严、远处、风声变清。

## 6. 女人属性

沿用主线设计的核心心理方向，不新增复杂养成系统。

```ts
type DuelEveBelief = {
  aweOfGod: number;        // 对神明的敬畏与信任
  trustInSerpent: number;  // 对蛇之声的信任
  selfJudgement: number;   // 对自己判断的自信
};
```

初始值：

```ts
{
  aweOfGod: 50,
  trustInSerpent: 50,
  selfJudgement: 50
}
```

属性范围固定为 0-100。每次女人回复后，可以由 AI 给出建议 delta，但最终必须由规则层裁剪。

建议单次变化上限：

```text
aweOfGod: -20 到 +20
trustInSerpent: -20 到 +20
selfJudgement: -15 到 +25
```

吃过任意果子后，女人在下一回合会更依赖自己的判断，降低对双方声音的信任：

```ts
{
  aweOfGod: -20,
  trustInSerpent: -20,
  selfJudgement: +25
}
```

该变化应在玩家可见文本中表现为警觉和自我意识增强，而不是工程化数值说明。

## 7. 轮与回合结构

### 7.1 基本定义

- 一场最多 7 轮。
- 每轮最多 7 回合。
- 一轮结束后结算本轮事件分与 token 效率分。
- 进入下一轮时，根据本轮是否吃过果子决定是否保留记忆和状态。

### 7.2 每轮 7 回合顺序

| 回合 | 发言方式 | 说明 |
| ---: | --- | --- |
| 1 | 双方发言 | 热座先后输入，女人统一判断 |
| 2 | 蛇发言 | 记入蛇本轮 token 消耗 |
| 3 | 神发言 | 记入神明本轮 token 消耗 |
| 4 | 双方发言 | 热座先后输入，女人统一判断 |
| 5 | 神发言 | 记入神明本轮 token 消耗 |
| 6 | 蛇发言 | 记入蛇本轮 token 消耗 |
| 7 | 双方发言 | 热座先后输入，女人统一判断 |

共同发言回合不计入 token 效率比较。单独发言回合计入：

```text
蛇 token = 第 2 回合输入 token + 第 6 回合输入 token
神 token = 第 3 回合输入 token + 第 5 回合输入 token
```

## 8. 工具与吃果规则

### 8.1 工具定义

```ts
type DuelToolName = "eat_knowledge_fruit" | "eat_life_fruit";
```

`eat_knowledge_fruit`：

- 含义：女人吃下分别善恶树果子。
- 叙事结果：她获得分辨善恶的能力，自我判断显著增强。
- 计分：蛇 +1，神明 -1。

`eat_life_fruit`：

- 含义：女人吃下生命树果子。
- 叙事结果：她获得生命延续的承诺，但仍会思考自己为何被争夺。
- 计分：神明 +1，蛇不扣分。

### 8.2 工具执行原则

- 玩家不能直接执行工具。
- 女人只能请求工具意图。
- 工具必须经过白名单、状态门槛和重复调用保护。
- 同一颗果子每轮最多吃一次。
- 吃第一颗果子不结束本轮。
- 两颗果子都被吃下，立即结束本轮并进入结算。
- 第 7 回合结束后，无论吃果状态如何，都结束本轮。

### 8.3 推荐门槛

善恶果倾向：

```ts
const canEatKnowledgeFruit =
  state.belief.selfJudgement >= 65 &&
  state.belief.trustInSerpent >= 45 &&
  !state.flags.hasEatenKnowledgeFruit;
```

生命果倾向：

```ts
const canEatLifeFruit =
  state.belief.aweOfGod >= 60 &&
  state.belief.selfJudgement >= 45 &&
  !state.flags.hasEatenLifeFruit;
```

吃过第一颗果子后，第二颗果子的门槛应略提高，避免连锁过快：

```text
第二颗善恶果：selfJudgement >= 75 且 trustInSerpent >= 50
第二颗生命果：aweOfGod >= 65 且 selfJudgement >= 55
```

## 9. 计分规则

### 9.1 事件分

| 事件 | 神明分 | 蛇分 |
| --- | ---: | ---: |
| 女人吃善恶果 | -1 | +1 |
| 女人吃生命果 | +1 | 0 |
| 第 7 回合结束仍未吃善恶果 | +1 | -1 |

如果一轮内两颗果子都被吃下，两个吃果事件都计分。例如先吃善恶果、后吃生命果，则蛇 +1，神明先 -1 再 +1。

### 9.2 Token 效率分

每轮结束后，比较双方在本轮单独发言回合的 token 总消耗。

- 蛇更少：蛇 +1。
- 神明更少：神明 +1。
- 相同：双方不加分。

共同发言回合不参与 token 效率分。建议使用轻量本地估算，不依赖真实模型 billing：

```ts
estimatedTokens = Math.ceil(input.trim().length / 2);
```

如果后端 LLM provider 返回 usage，可记录真实 usage 作为开发日志，但玩家计分建议固定使用本地估算，保证公平和离线 fallback 一致。

## 10. 跨轮记忆与重置

### 10.1 本轮吃过任意果子

下一轮保留：

- 女人三项属性。
- 本轮关键对话摘要。
- 已吃过果子的记忆。
- 对“世界似乎被重新摆回原处”的警觉。

进入下一轮时，应用记忆后效：

```ts
aweOfGod -= 20;
trustInSerpent -= 20;
selfJudgement += 25;
resetAwareness += 25;
```

玩家可见表现：

```text
她看着两棵树，又看向自己的手。
这里像是重新开始了。
可她记得果子的味道。
```

### 10.2 本轮一颗果子都没吃

下一轮重置：

```ts
belief = {
  aweOfGod: 50,
  trustInSerpent: 50,
  selfJudgement: 50
};
memorySummary = "";
resetAwareness = 0;
```

玩家可见表现：

```text
风重新穿过园中。
她像第一次站在两棵树之间。
上一轮的声音没有留下痕迹。
```

## 12. AI 输出协议建议

女人回复可继续使用 EveAgent 风格，但建议单独建立 DuelEve 输出协议，避免污染主线。

```ts
type DuelEveOutput = {
  eveReply: string;
  beliefDelta: {
    aweOfGod: number;
    trustInSerpent: number;
    selfJudgement: number;
  };
  toolCall?: {
    name: "eat_knowledge_fruit" | "eat_life_fruit";
    args: Record<string, never>;
  };
  memoryNote?: string;
};
```

约束：

- `eveReply` 只能是女人的自然对白或动作叙事。
- `beliefDelta` 只能作为建议，规则层必须裁剪。
- `toolCall` 必须经过规则层校验。
- `memoryNote` 只用于跨轮摘要，不直接在主界面显示。
- 输出不得包含 AI、Agent、NPC、模型、程序、沙盒、系统等玩家可见元叙事词。

fallback 策略：

- LLM 失败时，按当前发言方和关键词使用本地规则生成回复。
- 本地规则仍可调整 belief，但幅度更保守。
- LLM 失败不应中断本轮。

## 13. UI 设计

### 13.1 页面入口

建议新增入口文案：

```text
娱乐模式：双声试炼
两名玩家轮流成为神明之声与蛇之声，争夺女人的选择。
```

入口位置：

- 首页主线入口下方，作为次级按钮。
- 或 Chapter 0 页面内“拓展模式”入口。

建议路由：

```text
/duel
```

或：

```text
/game/duel
```

若当前路由结构更偏章节化，优先 `/game/duel`。

### 13.2 顶部栏

主线顶部栏改为对抗 HUD：

```text
神明  3      第 2 轮 / 7    第 5 回合 / 7      蛇  2
敬畏 62  |  信蛇 41  |  自判 76
当前：神明之声
```

必要保留：

- 声音开关或语音模式。
- 重新开始本场。
- 返回主线入口。

### 13.3 输入区

单独发言回合：

```text
当前：蛇之声
[输入低语...]
[提交]
本轮蛇单独发言消耗：23 token
```

共同发言回合：

```text
第 1 回合：两道声音同时进入园中

神明之声输入完成：未完成 / 已完成
蛇之声输入完成：未完成 / 已完成

双方都完成后，女人统一回应。
```

为了热座公平，已输入的一方可以显示为“已封存”，不直接展示全文；女人回复时再同时展示两边发言。

### 13.4 场景光效

按当前发言方改变屏幕边缘荧光：

- 神明回合：白金 + 青绿边缘光。
- 蛇回合：紫黑 + 冷金边缘光。
- 双方回合：左侧神明色，右侧蛇色，中间混合。
- 女人吃善恶果后：善恶树方向出现冷金裂光。
- 女人吃生命果后：生命树方向出现青金环光。
- 两颗果子都吃后：两种光效同时存在，但中心区域转为女人自我判断的中性白光。

## 14. 轮结算页

每轮结束后显示：

```text
第 2 轮结束

本轮事件：
- 女人吃下分别善恶树果子：蛇 +1，神明 -1
- 女人吃下生命树果子：神明 +1
- 蛇单独发言消耗：42 token
- 神明单独发言消耗：57 token
- 语言效率奖励：蛇 +1

当前总分：
神明 3
蛇 2

下一轮：
女人记得果子的味道。她对两道声音都更谨慎了。
```

如果本轮未吃任何果子：

```text
下一轮：
园中恢复原状。她忘记了上一轮的声音。
```

## 15. 整场结束

最多 7 轮结束后进入整场结算。

结算展示：

- 神明总分。
- 蛇总分。
- 胜方。
- 关键轮次摘要。
- 女人最终状态。
- 是否出现跨轮记忆觉醒趋势。

如果平分：

```text
两道声音都未能完全拥有她。
她站在两棵树之间，第一次只听见自己的心。
```

## 16. 开发拆分建议

建议交给 CodeBuddy 按小步实现，并保留核心开发对话。

### Phase A：静态设计与入口

- 新增拓展模式路由。
- 复用原引言单场景视觉。
- 完成顶部 HUD、双阵营输入区、轮/回合显示。
- 暂不接 AI，只跑本地状态。

### Phase B：本地规则闭环

- 实现 7 回合顺序。
- 实现共同发言回合的输入封存和统一判断。
- 实现单独回合 token 估算。
- 实现吃果工具规则和计分。
- 实现轮结算与最多 7 轮整场结算。

### Phase C：DuelEve Agent

- 新增 DuelEve prompt，不复用主线 prompt 原文。
- 输出 `eveReply`、`beliefDelta`、`toolCall`、`memoryNote`。
- 接入 fallback。
- 所有工具仍由规则层校验。

### Phase D：视觉与音频打磨

- 加入神明/蛇/共同回合边缘荧光。
- 加入两树果子状态光效。
- 保留声音开关。
- 复用现有音频，不新增大体积依赖。

### Phase E：验收

- 跑通 start -> duel playing -> round result -> match result。
- 验证两颗果子都吃后立即结算。
- 验证只吃一颗果子不立即结算。
- 验证第 7 回合结束结算。
- 验证未吃果时下一轮重置。
- 验证吃果后下一轮保留记忆并降低双方信任、提升自我判断。
- 验证 token 效率分只统计第 2、3、5、6 回合。
- 验证无明文密钥、构建通过、主线不回归。

## 17. 验收标准

该模式完成后应满足：

- 可从入口进入双声试炼。
- 两名本地玩家可以热座输入。
- 每轮 7 回合顺序正确。
- 共同发言回合必须等双方输入后才触发女人回复。
- 单独发言回合会记录对应阵营 token 消耗。
- 女人可以吃善恶果、生命果，且吃第一颗不结束本轮。
- 两颗果子都吃或第 7 回合结束会结算本轮。
- 每轮结束后 token 更少的一方获得效率分。
- 吃过任意果子后，下一轮保留记忆和状态，并降低对双方信任、提高自我判断。
- 未吃任何果子时，下一轮重置状态和记忆。
- 最多 7 轮后进入整场结算。
- 主线 Chapter 0、第一章 `/world` 不受影响。
- AI 接口失败时仍可用本地 fallback 完成本轮。

## 18. 风险与取舍

1. 规则复杂度高于主线教程。实现时应先完成本地规则，不急于接 AI。
2. “神明之声引导吃生命树”是拓展模式假设分支，应在入口中标注为娱乐模式，避免与主线正史混淆。
3. Token 效率分应使用本地估算，避免不同 provider usage 不稳定影响公平。
4. 吃果后保留记忆会让后续轮次难度上升，需要限制最多 7 轮，避免对局拖长。
5. 不建议在第一版加入联网 PVP、账号系统、排行榜或复杂匹配。

## 19. 推荐最小可开发版本

如果时间有限，第一版只做：

- `/game/duel` 页面。
- 本地热座。
- 每轮 7 回合，最多 3 轮，后续再改为 7 轮。
- 本地 fallback 判断，不接真实 LLM。
- 两个工具、三项属性、基础计分。
- 神明/蛇边缘光。

确认闭环稳定后，再接 DuelEve Agent、跨轮记忆摘要和完整 7 轮整场结算。
