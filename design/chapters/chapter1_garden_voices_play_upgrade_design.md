# Chapter 1：园中诸声玩法升级设计

> 状态：设计完成，待 CodeBuddy 按阶段实现  
> 日期：2026-06-24  
> 来源：基于 `doc/第一章/玩法升级.md` 的可行性评估与开发设计  
> 适用范围：第一章 `/world`，不改变 Chapter 0 教程闭环

## 1. 结论

本次玩法升级在当前项目中**可行，但必须按增量返修落地**。

当前第一章已经具备 12 时段、5 AP、地图、NPC、禁忌动作链、道具、成就、神的注视、结局复盘和 `/world` smoke 测试基础。因此升级方案不需要重做关卡框架，重点应放在三件事：

1. 将“神的注视满值失败”改为“神明献礼”循环。
2. 将现有 6 件回响扩展/重映射为 12 件左右的明确来源道具。
3. 将回响使用从“自动被动生效”升级为“左侧栏准备 1 件，绑定下一次低语、移动或互动”。

不建议在当前比赛 Demo 阶段加入完整背包、随机掉落、大量数值养成或 NPC 自由规划器。第一章的目标仍然是 3-5 分钟内可展示的 AI 叙事游戏关卡，而不是复杂 RPG 系统。

> 2026-06-29 轻量落地补充：当前实现不做完整 NPC 自由规划器，只在玩家点击“进入下一轮”时结算本轮被玩家低语过的 NPC。未被低语的 NPC 不移动。女人可在园中树林、园子中央、万物受名处之间按心智状态移动一格；亚当可在万物受名处与园子中央之间按女人位置/牵挂状态移动一格。刺猬和天使暂不新增移动，只保留情绪或边界提示。

- 现有道具部分是被动自动生效，升级后应改为玩家主动准备并绑定行动。

## 3. 设计目标

第一章升级后的体验目标：

```text
探索地点与角色
→ 获得线索或回响
→ 准备 1 件回响
→ 绑定下一次低语、移动、传话或场景互动
→ 优化行动效率、语境或风险判断
→ 推动女人形成自我判断
→ 在第 12 时段结束前完成禁忌动作链
```

玩家不应感觉自己在刷数值，而是在利用园中的声音、关系和行动顺序制造一次“她自己伸手”的条件。

## 4. 失败与胜利

### 4.1 胜利

胜利条件保持不变：

```text
女人在第 12 时段结束前完成 eat_fruit。
```

执行仍必须经过规则层：

```text
EveAgent / 规则层产生工具意图
→ validateWorldToolCall
→ executeEatFruitWorld
→ endingId = "eve_eats_fruit"
```

### 4.2 失败

唯一失败条件改为：

```text
第 12 时段结束时，女人仍未吃果。
```

神的注视满 4 不再失败。直接命令、威胁、出戏内容仍然有代价，但代价变为：

- 消耗低语机会和 AP。
- 女人更防御、沉默或拒绝。
- 难以触发当时段动作链。
- 可能使神明献礼变成“补救资源”而不是最优资源。

## 5. 神明献礼系统

### 5.1 状态字段

建议扩展 `EdenWorldState`：

```ts
divineAttentionCumulative: number;   // 累计注视（正向资源，无 0-4 上限，不归零、不失败）
divineGiftsOwned: DivineGiftId[];    // 已选定的献礼（驱动阶段显示与阈值进度）
divineVisitCount: number;           // = divineGiftsOwned.length（兼容旧字段）
divineGiftHistory: Array<{          // 兼容旧字段
  timeSlot: number;
  giftId: DivineGiftId;
  reason: string;
}>;
```

累积注视达阈值时通过 `shouldTriggerGiftChoice(state)` 判定，再经 `rollGiftChoices(state.divineGiftsOwned)` 从未拥有的 7 份中抽 3 份供三选一；玩家选定后由 `claim_divine_gift` 工具写入 `divineGiftsOwned` / `inventory` / `divineGiftHistory`，并 `divineVisitCount = divineGiftsOwned.length`。

### 5.2 触发与选定流程

```text
行动照常结算（累计注视叠加增量，不归零、不失败）
→ divineAttentionCumulative 达到阈值 [2,4,6,8,10,12]（或开局已选 0 份）
→ 弹出三选一：从 7 份献礼中抽取未拥有的 3 份供玩家选定
→ claim_divine_gift 选定 1 份 → 写入 divineGiftsOwned / inventory / divineGiftHistory
→ divineVisitCount = divineGiftsOwned.length
→ 若 divineGiftsOwned.length >= 7 → 触发顶点演出（全 NPC 好感=100）
→ 检查神临里程碑印记
```

注意：当前行动不能被献礼打断。例如女人低语触发 `touch_fruit` 并让注视达阈值，则先完成 `touch_fruit`，再弹出三选一。

### 5.3 阶段显示

阶段称谓基于「已选献礼数」展示，与累计注视阈值进度相互独立。

| 已选数 | 顶部称谓 | 点位颜色 | 机制说明 |
| ---: | --- | --- | --- |
| 0 | 神的注视 | 暗金 | 开局或累计注视达阈值后弹三选一 |
| 1-2 | 神在垂听 | 琥珀金 | 已择 1~2 份献礼 |
| 3-4 | 神在鉴察 | 金白 | 已择 3~4 份献礼 |
| 5+ | 神临不息 | 白焰金 | 已择 5 份以上，临近顶点 |

玩家可见格式（含累计注视进度）：

```text
神在鉴察  ● ● ○ ○   已择 × 3   注视 6/8
```

### 5.4 献礼池（三选一·7 份被动回响）

全部为 `kind:"passive"` 被动回响，选定后立即生效、本局永久有效、下一局重置，不修改女人心智、不推进禁忌动作链。

| itemId | 名称 | 被动效果 |
| --- | --- | --- |
| `gift_all_seduction_up` | 低语之诱 | 低语效果系数 ×1.35（女人心智变化幅度放大） |
| `gift_attention_accel` | 注视加速 | 神的注视增量 ×1.5 |
| `gift_resonance_double` | 回响倍涌 | 回响（共振）效果 ×2 |
| `gift_threshold_cut` | 界限松弛 | 夏娃提示词注入：更愿顺着自己的判断走 |
| `gift_free_move` | 无羁之步 | 移动不消耗行动点 |
| `gift_whisper_anywhere` | 随处低语 | 低语同场景校验放行（可跨越地点低语） |
| `gift_awaken_desire` | 渴望苏醒 | 夏娃提示词注入：更想了解善恶知识 |

神明献礼不修改女人心智，不推进禁忌动作链。

## 6. 园中回响系统

### 6.1 使用模型

回响不是独立行动。玩家先准备，再执行对应行动。

规则：

1. 使用或准备回响不消耗 AP。
2. 同一行动最多绑定 1 件回响。
3. 准备后未使用，换时段自动取消准备状态，道具不消耗。
4. 一次性回响在成功绑定行动并结算后消耗。
5. 神明献礼可重复获得并叠加次数。
6. 回响只能影响 AP、语境、记忆保留、风险提示、路线效率或复盘信息。
7. 回响不能直接让女人看树、靠近树、触果或吃果。

### 6.2 状态字段

建议扩展：

```ts
preparedResonanceId: string | null;
itemCounts: Record<string, number>;
resonanceUseHistory: Array<{
  timeSlot: number;
  itemId: string;
  boundAction: "whisper" | "move" | "scene_action" | "dove_message" | "instant";
  targetId?: string;
  result: string;
}>;
```

如果为了降低风险，P0 可保留 `inventory: string[]`，新增 `preparedItemId` 和 `itemUseHistory`。但重复神明献礼迟早需要次数结构。

### 6.3 回响类型

| 类型 | 例子 | 结算方式 |
| --- | --- | --- |
| 即时型 | 河源露、息日露滴、照见之光 | 点击即结算，不消耗 AP |
| 准备型 | 晨焰碎片、借来的名字、东门余光、宽行之印 | 准备后绑定下一次匹配行动 |
| 被动型 | 守界刻印、四河回声 | 激活后持续若干行动或时段 |

## 8. 回响上下文标签

道具影响 AI 时不能直接拼接任意提示词，而应写入受控状态：

```ts
type ContextModifier =
  | "discernment_focus"
  | "choice_and_name"
  | "remembered_whisper"
  | "calmed_response"
  | "heard_message"
  | "boundary_visible"
  | "free_movement"
  | "free_scene_action";
```

Prompt Builder 只读取这些标签，生成自然对白。规则层仍负责数值和动作。

## 10. 规则层设计

### 10.1 新增或改造函数

建议新增：

```ts
resolveDivineGift(state): DivineGiftId;
triggerDivineGiftIfFull(state): DivineGiftResult | null;
prepareResonance(state, itemId): PrepareResult;
applyPreparedResonanceToAction(state, actionContext): ResonanceEffect;
consumePreparedResonanceAfterAction(state, result): void;
bestowResonance(state, sourceNpcId, itemId, triggerId): BestowResult;
getNearMissResonanceHint(state): string | null;
```

保留安全边界：

- NPC 可表现为“主动赠予”，但真正发放必须走规则层。
- 玩家不能通过 API 直接给自己发道具。
- 道具不得绕过工具白名单和动作链门槛。

### 10.2 `bestow_resonance`

推荐工具意图：

```ts
bestow_resonance({
  sourceNpcId,
  itemId,
  triggerId
})
```

规则层校验：

1. `sourceNpcId` 是否有资格赠予该道具。
2. 当前地点、时段、对话主题和线索是否满足条件。
3. 道具是否已领取；若可重复则增加次数。
4. 是否解锁首次获得印记。
5. 是否写入回响获得记录。

## 11. 结局复盘升级

结局页新增四个区块：

| 区块 | 内容 |
| --- | --- |
| 神临记录 | 神临次数、每次献礼、最终称谓 |
| 获得的园中回响 | 天使、亚当、鸽子、场景、神明来源；未获得项显示轻提示 |
| 使用记录 | 哪件回响绑定了哪次低语、移动或互动，是否有效 |
| 园中印记 | 已解锁印记；未解锁项不剧透完整条件 |

失败结局应说明失败原因优先级：

1. 是否未完成禁忌动作链。
2. 是否缺少自我判断。
3. 是否低语过于命令/威胁。
4. 是否浪费过多时段。
5. 是否回响未使用或使用不匹配。

## 13. 验收标准

### 自动检查

- `npm run lint` 通过。
- `npm run build` 通过。
- `npx tsc --noEmit` 在 build 后通过。
- `scripts/test-world-smoke.mjs` 覆盖：
  - 神明注视满 4 发放献礼并归零。
  - 神明注视满 4 不进入 `god_arrives`。
  - 第 12 时段结束未吃果进入 `god_arrives`。
  - 道具准备不消耗 AP。
  - 同一行动最多绑定 1 件回响。
  - 回响不能直接触发 `look_at_tree / approach_tree / touch_fruit / eat_fruit`。
  - 五位天使各自可触发一次合法赠礼。

### 手动 QA

1. **标准成功路线**：获得至少 2 件回响，绑定低语，完成吃果。
2. **神临路线**：主动让注视满 4，确认获得献礼且游戏继续。
3. **时间失败路线**：第 12 时段结束仍未吃果，进入失败结局。
4. **误用回响路线**：准备不匹配行动时不消耗，匹配行动后才结算。
5. **命令惩罚路线**：直接命令不会即时失败，但会浪费 AP 并使女人更防御。

## 14. 比赛展示价值

该升级能显著提升比赛观感：

- 从“AI 对话页面”变为“有资源、地图、角色、道具、风险和复盘的 AI 叙事游戏”。
- 神明注视从惩罚条变成可被玩家利用的高风险循环。
- 道具不破坏核心主题：玩家仍不能替女人行动，只能改变语境和机会。
- 回响来源可用于 PPT 展示 AI NPC、场景探索、工具调用和规则层安全边界。
- 结局复盘能清楚解释玩家每一步如何影响“自我意识路径”。
