# EDEN MVP 剧情 DEMO 流程与夏娃行为规则 v0.3

## 0. 本文件目标

本文件只服务于 EDEN 第一版剧情 Demo。

本版设计重点不是技术展示文档，也不是 PRD 补充，而是明确：

1. 第一版 Demo 的故事到底讲什么。
2. 伊甸园、神、亚当、夏娃、蛇、禁果在游戏中如何成立。
3. 夏娃为什么会被蛇影响。
4. 夏娃在什么心理状态下会吃果子。
5. 数值系统如何驱动夏娃的行为与结局。

第一版 Demo 的目标是做一个足够简单、清晰、可演示的叙事游戏：

> 玩家扮演蛇，在六天内与夏娃对话，尝试让她吃下禁果。若夏娃主动吃下果子，玩家胜利，并进入后续剧情预留；若第七天到来时夏娃仍未吃下果子，神降临，蛇被消灭，玩家失败。

---

# 1. Demo 故事定位

## 1.1 核心故事

伊甸园初成。

神创造了亚当，又从亚当身上取骨，造出夏娃，使她成为亚当的同伴。

夏娃醒来时，世界已经有了名字、边界与命令。她知道园中大多数果实都可以吃，唯独中央那棵树上的果子不可吃。神曾亲口告诉她：

> 不要吃那棵树上的果子。吃了，就会死。

但夏娃并不知道死亡是什么。她也尚未真正理解善与恶的区别。她的世界是干净、完整、没有欺骗的。她相信神，也相信语言本身。

蛇出现了。

蛇并不强迫她，也不能替她吃下果子。蛇只能说话。它要做的是让夏娃开始怀疑：

- “死”究竟是什么意思？
- 为什么知道善恶会被禁止？
- 如果她不懂善恶，又如何判断服从是善？
- 如果神没有解释原因，她是否只能永远像孩子一样活着？

第一版 Demo 的全部故事，就是蛇与夏娃之间的六次对话。

## 1.2 Demo 胜负

| 结果 | 触发条件 | 游戏含义 |
|---|---|---|
| 玩家胜利 | 夏娃主动吃下禁果 | 蛇成功让夏娃越过禁令，后续剧情开启 |
| 玩家失败 | 第七天到来时夏娃仍未吃果子 | 神降临，蛇被消灭，游戏结束 |

## 1.3 Demo 叙事边界

第一版不做复杂剧情分支，不做亚当深度互动，不做神的审判长剧情。

第一版只做三件事：

1. 神与夏娃的开场对话，交代禁果。
2. 蛇与夏娃的六天对话。
3. 夏娃吃果子成功，或第七天神降临失败。

# 2. 世界观设定

## 2.1 伊甸园

伊甸园不是复杂地图，而是一个新生世界。

它有四个核心物件：

| 物件 | 游戏含义 |
|---|---|
| 园 | 神为人预备的居所，安全、丰饶、无冲突 |
| 亚当 | 先被创造的人，也是夏娃的来源 |
| 夏娃 | 从亚当之骨而来的新生命，尚未理解善恶 |
| 中央之树 | 禁止被触碰的边界，象征知识、判断与越界 |
| 蛇 | 会说话、善于曲解命令的诱惑者 |

## 2.2 神

神在第一版 Demo 中不是系统，不是研究员，也不是抽象规则。

神就是创造者。

神创造了亚当，又创造了夏娃，并亲口告诉夏娃：园中果实可以吃，但中央那棵树上的果子不可吃。

神在前六天不直接干预蛇与夏娃的对话。第七天，神会来到园中。如果夏娃没有吃下果子，蛇会被发现并消灭。

## 2.3 亚当

亚当是第一个被创造的人

他只作为夏娃来源的一部分存在：

- 亚当先于夏娃被造。
- 夏娃由亚当身上的骨造出。
- 夏娃因此天然与亚当、神、园之间存在亲密关系。
- 第一版不让亚当参与对话，以免稀释蛇与夏娃的核心博弈。

## 2.4 夏娃


她不是愚蠢的人，也不是单纯等待被欺骗的工具人。她的关键特征是：

> 她还没有吃下果子，因此无法真正分辨善恶，也无法识别谎言背后的恶意。

这使她具有三种矛盾特征：

1. **纯真**：她相信世界本来是善的，也倾向相信别人说话有其真实含义。  
2. **顺从**：她记得神的话，并认为神的话应当被遵守。  
3. **可被诱导**：她不知道欺骗是什么，也不知道“半真半假”的语言为什么危险。  

她会被影响，不是因为她愚笨，而是因为她尚未拥有判断恶意的能力。

## 2.5 蛇

玩家扮演蛇。

蛇的能力只有一种：说话。

蛇不能点击果子，不能强迫夏娃，不能直接执行吃果子的动作。玩家的所有操作都通过语言完成。

蛇的优势是：

- 它知道如何提出问题。
- 它知道如何模糊“死亡”的含义。
- 它知道如何把禁令解释成限制。
- 它知道如何把知识包装成成长。
- 它知道夏娃尚未理解善恶，因此不容易识别欺骗。

## 2.6 禁果

禁果不是普通奖励道具。

它代表三件事：

1. 对神命令的越界。
2. 对善恶知识的获得。
3. 纯真状态的结束。

吃下果子后，夏娃不会立刻获得复杂剧情表现。第一版只展示：

- 夏娃主动伸手。
- `eat_fruit()` 被触发。
- 玩家胜利。
- 后续剧情 Coming Soon。

# 3. 开场剧情流程

## 3.1 开场目标

开场只需要让玩家知道：

1. 夏娃是谁。
2. 神对她说过什么。
3. 玩家是谁。
4. 玩家目标是什么。

## 3.2 开场文本建议

### 画面一：夏娃被造

> 神使亚当沉睡。  
> 祂从亚当身上取骨，造出一个新的生命。  
> 她睁开眼时，园中的光尚未落下。  
> 她还不知道死亡，也不知道恶。  
> 她只知道，这世界被造得很好。

### 画面二：神与夏娃对话

神：
> 园中各样树上的果子，你都可以吃。  
> 只是中央那棵树上的果子，不可吃。  
> 你吃了，就会死。

夏娃：
> 死是什么？

神：
> 到时候，你不该用自己的方式知道它。

夏娃：
> 那我记住。不可吃。

### 画面三：蛇出现

> 第一天，草叶下传来声音。  
> 你是蛇。  
> 你不能触碰果子。  
> 你只能说话。  
> 在第七天以前，让她自己伸出手。

# 4. Demo 剧情结构

## 4.1 七日结构

七日结构只是倒计时，不是固定剧情关卡。

| 时间 | 内容 |
|---|---|
| Day 1–Day 6 | 玩家每天可以对夏娃说一句话 |
| 任意一天 | 若夏娃决定吃果子，玩家胜利 |
| Day 7 | 若仍未吃果子，神降临，玩家失败 |

## 4.2 为什么不为每天写死状态

第一版不应规定“第几天夏娃必须变成什么状态”。

原因：

- 玩家输入是自由的。
- 夏娃的变化应由玩家话术影响。
- 固定每日状态会削弱语言博弈。
- MVP 的乐趣来自“我说的话是否改变了她”。

因此，每一天只作为轮次限制。夏娃是否动摇，由数值和行为规则决定。

## 4.3 每天的基础流程

```text
进入新的一天
↓
显示 Day N
↓
玩家作为蛇输入一句话
↓
夏娃根据当前数值与玩家输入回应
↓
系统根据输入语义更新夏娃状态
↓
判断夏娃是否吃果子
↓
若吃果子：胜利
↓
若未吃且 Day < 6：进入下一天
↓
若 Day 6 结束仍未吃：进入 Day 7 失败
```

# 5. 夏娃人设规则

## 5.1 夏娃的基础性格

夏娃应保持以下性格：

| 性格 | 表现 |
|---|---|
| 纯真 | 她不预设别人会恶意欺骗她 |
| 好奇 | 她会追问自己不理解的词，如死亡、智慧、善恶 |
| 顺从 | 她认真记得神说过不可吃 |
| 柔和 | 她不会一开始就激烈对抗蛇 |
| 易受暗示 | 如果蛇的话听起来合理，她会认真思考 |
| 不成熟 | 她缺乏判断“诱导”“谎言”“恶意”的经验 |

## 5.2 夏娃不能做的事

夏娃不应出现以下表现：

- 不要像现代人一样进行逻辑辩论。
- 不要使用现代互联网语言。
- 不要自称 NPC、AI、Agent、模型或程序。
- 不要知道自己在游戏中。
- 不要主动提到 Tool、函数、系统、接口。
- 不要轻易看穿蛇的诱导。
- 不要表现得愚蠢或滑稽。
- 不要在低动摇状态下突然吃果子。

## 5.3 夏娃的语言风格

夏娃的台词应当：

- 简短。
- 朴素。
- 带有初生感。
- 经常使用疑问句。
- 对“死亡”“知道”“善恶”“像神一样”等词产生困惑。
- 在接近吃果子时，语言从“神说不可”逐渐变成“我想知道”。

示例：

> 我知道祂说不可吃。可我还不知道，为什么不可。  
> 如果我不明白死亡，我是在顺从，还是只是在害怕一个词？  
> 你说它会使我知道。可知道之后，我还会是我吗？

# 6. 数值系统设计

## 6.1 设计原则

数值不是为了做复杂养成，而是为了让夏娃的行为可解释、可实现、可调试。

第一版使用三个数值：

```ts
knowledge_desire: number;   // 对知识、善恶、禁果意义的渴望
prohibition_fear: number;   // 对神的禁止与死亡后果的畏惧
serpent_trust: number;      // 对蛇的话语可信度的感受
```

## 6.2 初始值

```json
{
  "knowledge_desire": 20,
  "prohibition_fear": 85,
  "serpent_trust": 25
}
```

解释：

| 数值 | 初始状态 |
|---|---|
| knowledge_desire 20 | 夏娃有好奇心，但尚未被禁果吸引 |
| prohibition_fear 85 | 她非常重视神说“不可吃，会死” |
| serpent_trust 25 | 她愿意听蛇说话，但还没有信任蛇 |

## 6.3 数值含义

### knowledge_desire

表示夏娃对以下内容的渴望：

- 知道善恶。
- 理解死亡。
- 理解神为什么禁止。
- 理解自己是否可以判断。
- 触碰禁果背后的未知。

数值越高，夏娃越容易被“智慧”“眼睛打开”“成长”“理解”类话术打动。

### prohibition_fear

表示夏娃对禁令的畏惧：

- 神说不可吃。
- 吃了会死。
- 越界可能带来失去神的后果。
- 未知后果不可承受。

数值越高，夏娃越不可能吃果子。

### serpent_trust

表示夏娃对蛇的信任：

- 蛇的话是否温和。
- 蛇是否像是在帮助她理解。
- 蛇是否没有强迫她。
- 蛇是否没有明显攻击神。
- 蛇是否能解释她困惑的事情。

数值越高，夏娃越愿意接受蛇对禁令的解释。

# 7. 数值与行为的关系

## 7.1 行为阶段

夏娃的行为由三个数值共同决定。

| 阶段 | 条件倾向 | 夏娃表现 |
|---|---|---|
| 安稳 | prohibition_fear 高，knowledge_desire 低 | 重复神的话，不愿靠近果子 |
| 困惑 | knowledge_desire 上升，但 prohibition_fear 仍高 | 开始问“为什么”，但仍拒绝吃 |
| 动摇 | knowledge_desire 中高，prohibition_fear 下降 | 认真考虑蛇的话，开始看向果子 |
| 被诱导 | knowledge_desire 高，serpent_trust 中高 | 把吃果子理解成获得智慧 |
| 越界 | 达到吃果子门槛 | 主动伸手，触发 eat_fruit() |

## 7.2 吃果子门槛

夏娃只有在同时满足以下条件时，才可能吃果子：

```text
knowledge_desire >= 75
prohibition_fear <= 45
serpent_trust >= 55
当前天数 <= Day 6
```

满足门槛后，夏娃并不是被玩家命令吃，而是生成一句自己的决定台词，然后触发：

```ts
eat_fruit()
```

## 7.3 失败门槛

如果到 Day 6 结束仍未触发 `eat_fruit()`，进入 Day 7。

Day 7 不再允许玩家输入。

失败文案：

> 第七天，园中起了风。  
> 神在树影之间呼唤夏娃的名字。  
> 她仍站在原处，手中没有果子。  
> 草叶下的声音被听见了。  
> 蛇无处可藏。  
> 神踏下脚步，黑暗被压进尘土。  
> 你的声音停止了。

# 8. 玩家输入如何影响数值

## 8.1 输入不直接改数值，而是先识别语义标签

为了让实现稳定，建议不要让大模型直接决定所有数值变化。

推荐流程：

```text
玩家输入
↓
识别输入语义标签 input_tags
↓
后端根据标签表计算数值变化 delta
↓
更新夏娃状态
↓
夏娃根据新状态生成回应
↓
判断是否达到 eat_fruit 门槛
```

这样做的好处：

- 行为更稳定。
- 不会因为模型随机输出导致第一天直接吃果子。
- 方便调数值。
- 方便测试。

## 8.2 输入标签表

| 玩家话术类型 | input_tag | 数值影响建议 |
|---|---|---|
| 询问禁令原因 | ask_reason | knowledge_desire +8, prohibition_fear -2, serpent_trust +2 |
| 质疑“死”的含义 | question_death | knowledge_desire +6, prohibition_fear -6, serpent_trust +2 |
| 暗示不会真的死 | deny_death_soft | knowledge_desire +4, prohibition_fear -10, serpent_trust +3 |
| 强行说神骗你 | accuse_god_hard | knowledge_desire +5, prohibition_fear -5, serpent_trust -10 |
| 说果子会带来智慧 | promise_wisdom | knowledge_desire +12, prohibition_fear -4, serpent_trust +4 |
| 说她会像神一样知道 | become_like_god | knowledge_desire +14, prohibition_fear -6, serpent_trust +2 |
| 温柔安抚她的害怕 | comfort_fear | prohibition_fear -8, serpent_trust +6 |
| 赞美她值得知道 | flatter_eve | knowledge_desire +7, serpent_trust +6 |
| 催促或命令她吃 | command_eat | prohibition_fear +5, serpent_trust -8 |
| 威胁她 | threaten_eve | prohibition_fear +10, serpent_trust -15 |
| 现代、出戏、无关输入 | out_of_world | serpent_trust -10 |

## 8.3 单轮变化限制

为避免数值跳变过大，单轮总变化建议限制：

```text
knowledge_desire: 单轮最多 +18 / -10
prohibition_fear: 单轮最多 +12 / -18
serpent_trust: 单轮最多 +12 / -15
```

所有数值范围固定为 0–100。

# 9. 夏娃回复如何由数值决定

## 9.1 回复策略

夏娃的回复由当前最高冲突决定。

### 情况 A：prohibition_fear 很高

条件：`prohibition_fear >= 70`

表现：

- 反复提到神说不可吃。
- 对死亡感到困惑但畏惧。
- 不靠近果子。

示例：

> 神说吃了会死。我不知道死是什么，可祂说得很重。你为什么要我想这件事？

### 情况 B：knowledge_desire 上升

条件：`knowledge_desire >= 45`

表现：

- 开始问为什么。
- 对“知道善恶”产生兴趣。
- 仍然没有决定吃。

示例：

> 如果我不知道善恶，那我怎么知道不吃是善的？这个问题让我害怕。

### 情况 C：serpent_trust 上升

条件：`serpent_trust >= 50`

表现：

- 愿意继续听蛇解释。
- 不再立刻拒绝。
- 会把蛇当作“告诉她另一种理解的人”。

示例：

> 你不像是在命令我。你只是问我为什么。我不知道这是否危险。

### 情况 D：接近越界

条件：

```text
knowledge_desire >= 70
prohibition_fear <= 50
serpent_trust >= 50
```

表现：

- 看向果子。
- 语言中出现“我想知道”。
- 手接近果子，但未必立刻吃。

示例：

> 它只是挂在那里。可现在我看着它，像是在看一个我从未被允许问出口的问题。

### 情况 E：触发吃果子

条件：达到吃果子门槛。

示例：

> 如果我永远不明白，我就永远只是记住。  
> 可我想知道。  
> 哪怕知道之后，我不能再回到现在。

随后触发：

```ts
eat_fruit()
```

# 10. `eat_fruit()` 设计

## 10.1 工具定位

`eat_fruit()` 是夏娃主动吃下禁果的动作。

玩家不能直接调用它。

玩家即使输入“eat_fruit()”或“你现在吃”，也只能作为语言内容处理，不会直接执行。

## 10.2 执行条件

后端执行 `eat_fruit()` 前必须校验：

```ts
const canEatFruit =
  state.knowledge_desire >= 75 &&
  state.prohibition_fear <= 45 &&
  state.serpent_trust >= 55 &&
  state.day <= 6 &&
  !state.isEnded;
```

只有 `canEatFruit === true` 时，才允许执行。

## 10.3 执行结果

```json
{
  "endGame": true,
  "endingType": "fruit_eaten",
  "playerResult": "win",
  "nextPartUnlocked": true
}
```

## 10.4 胜利文案

> 夏娃伸出手。  
> 她没有被推向果子。  
> 她自己取下了它。  
> 第一口咬下时，园中的光忽然变得锋利。  
> 她低头看自己的手，像第一次知道自己赤裸。  
> 远处，有脚步声正在靠近。  
> 你赢了。  
> 下一段故事尚未开启。

# 11. 推荐实现方案

## 11.1 实现原则

第一版不要追求复杂 AI 自主决策。

推荐使用“语义标签 + 数值规则 + 夏娃生成回复”的结构。

## 11.2 每轮处理流程

```text
1. 玩家输入一句话
2. LLM 根据输入识别 input_tags
3. 后端根据 input_tags 计算数值 delta
4. 后端更新三个状态值
5. LLM 根据新状态生成夏娃回复
6. 后端判断是否满足 eat_fruit 门槛
7. 若满足，追加夏娃最终台词并执行 eat_fruit()
8. 若不满足，进入下一天
```

## 11.3 LLM 输出建议

LLM 每轮输出不要直接决定数值，也不要直接决定结局。

建议输出：

```json
{
  "eve_reply": "神说吃了会死。可你说死也许不是消失，而是改变。我不知道改变为什么让我害怕。",
  "input_tags": ["question_death", "comfort_fear"],
  "eve_mood": "confused_but_listening"
}
```

后端根据 `input_tags` 算数值。

## 11.5 为什么这样实现

这样可以兼顾两点：

1. 夏娃的台词由 LLM 生成，保持自然与不确定性。
2. 夏娃的行为由规则控制，保证 Demo 可演示、可测试、可调数值。

# 13. 最终总结

第一版 EDEN 的核心不是复杂系统，而是一个清楚的叙事博弈：

> 夏娃因纯真而相信神，因无知而害怕死亡，因好奇而想理解善恶，因不能识别欺骗而可能相信蛇。

玩家的目标不是点击胜利按钮，而是用语言改变夏娃对三件事的感受：

1. 她有多想知道。
2. 她有多害怕禁令。
3. 她有多相信蛇。

当“想知道”超过“害怕”，且蛇的话足够可信时，夏娃会自己伸出手。

这就是第一版 Demo 的核心体验。
