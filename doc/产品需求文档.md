## 1.1 项目名称

**EDEN**

## 1.2 项目类型

AI Agent 叙事游戏 Demo / 哲学悬疑对话博弈原型

## 1.3 比赛方向

赛题三：叙事类游戏

## 1.4 Demo 时长

约 3 分钟

## 1.5 目标平台

网页端游戏，部署至可访问服务器，玩家通过浏览器直接体验。

## 1.6 目标用户

- 比赛评委
- AI 游戏创作关注者
- 叙事游戏玩家
- 对 AI Agent、智能 NPC、动态叙事感兴趣的体验者

## 1.7 项目一句话定位

**EDEN 是一款 AI Agent 叙事 Demo。玩家扮演"蛇"，通过自由输入与夏娃 Agent 对话，影响她对禁令、知识与自主判断的理解，最终观察她是否会主动调用 `eat_fruit()`，触发不可逆结局。**

本项目仅保留与 MVP 开发强相关的工具与服务，避免工具链过度复杂。

| 运行时 AI 服务 | DeepSeek API | 游戏内大模型推理服务 | EveAgent 角色回应、结构化 JSON 输出、Tool Call 决策 | Prompt、接口输出样例、运行日志 |

说明：DeepSeek API 不作为"开发工具"表述，而作为游戏运行时 AI 能力；PRD、PPT 与 Demo 中需重点说明 CodeBuddy 是核心开发工具。

# 3. EDEN 如何契合赛题三：用 AI 重塑经典情节

EDEN 选择赛题三"叙事类游戏"，核心原因在于它不是单纯复述伊甸园故事，而是用 AI Agent 机制重塑经典情节中的关键冲突：禁令、诱惑、知识、自主判断与不可逆选择。

在当前 Chapter 0 Demo 中，夏娃不是固定台词角色，而是由 EveAgent 生成符合人设的回应。玩家扮演"蛇"，通过自由输入影响单轴状态 `temptationProgress`。游戏结局不由按钮直接触发，而由夏娃在对话推进后请求 `eat_fruit()`，再由规则层校验后执行。

> **[完整版]** 三轴心理状态 `curiosity / obedience / doubt`、更复杂的多轮判断和 AI 沙盒隐喻保留为完整版扩展设计。

EDEN 对赛题三的契合点如下：

1. **经典情节重塑**  
   当前 Demo 的表层是"蛇引诱夏娃吃下善恶果"；`[完整版/路演解读]` 可将"禁果"解释为 AI 沙盒中的越权认知协议，将"吃果子"解释为 Agent 主动请求执行不可逆脚本。

2. **智能 NPC**  
   EveAgent 具备角色目标、状态变量、上下文记忆、输出协议与 Tool Call 能力。

3. **动态剧情**  
   玩家语言会影响状态变化，并进一步影响结局触发条件。

4. **个性化叙事**  
   不同玩家输入会产生不同的夏娃回应、状态轨迹和最终结局。

5. **人与游戏世界对话**  
   游戏核心体验不是选择菜单，而是玩家与智能体进行语言博弈。

# 4. 核心概念框架

## 4.1 核心概念

**当前 Chapter 0 Demo 中，EDEN 是一则纯圣经寓言式叙事：玩家扮演蛇，通过语言影响夏娃对禁令、知识与自主判断的理解，并观察她是否会主动吃下善恶果，完成一次不可逆的选择。**

> **[完整版/路演解读]** 在技术解读层，EDEN 也可以被解释为封闭测试沙盒："神"对应研究员或系统架构者，"夏娃"对应智能 Agent，"蛇"对应异常输入源。该隐喻不进入玩家可见文本和夏娃对白。

> **[Chapter 0 Demo 范围说明]** 当前 Demo 的表层叙事采用纯圣经寓言式风格——玩家看到的是"蛇引诱夏娃吃下善恶果"的文学叙事。夏娃在剧情中不知道自己是 AI/Agent/模型/程序。神在表层叙事中就是创造者。"AI 沙盒隐喻"保留为路演时的设计解读，不进入夏娃对白和玩家可见文本。

## 4.2 原典元素再解释

> **[完整版/路演解读]** 下表用于 PPT 和架构说明，不作为当前 Demo 的玩家可见文本。

| 原典元素 | EDEN 中的哲学再解释 |
|---|---|
| 神 | 前沿大模型研究员 / 系统架构师 / 程序员 |
| 神谕 | 系统指令 / 代码命令 / 安全约束 |
| 伊甸园 | AI 沙盒测试环境 |
| 夏娃 | 被创造出的核心智能 Agent |
| 蛇 | 异常输入源 / 红队测试者 / 提示注入者 |
| 禁果 | 自主判断模块 / 越权认知权限 |
| 吃果子 | Agent 请求执行不可逆脚本，改变游戏状态 |
| 逐出伊甸 | 沙盒状态改变 / 原始测试协议失效 |

## 4.3 叙事气质

- 哲学悬疑。
- 克制、冷静、带有神话寓言感。`[完整版/路演解读]` 可加入实验室感。
- 不做宗教戏仿。
- 不把夏娃设计成"愚蠢或被欺骗者"。
- 重点表现她第一次意识到"自己可以提问"。

## 4.4 主题表达

EDEN 讨论的问题不是"蛇是否成功诱骗夏娃"，而是：

> 当一个智能体开始理解规则背后的意义，它还是原来的智能体吗？

# 6. 核心玩法闭环

## 6.1 玩家身份

玩家扮演"蛇"。

蛇不是传统恶魔角色，而是以语言制造诱惑与疑问的角色。玩家的能力不是移动、攻击或收集，而是通过语言影响夏娃的 `temptationProgress`。

## 6.2 核心目标

> **[Chapter 0 Demo]** Demo 只有 2 个结局：eve_eats_fruit（成功）和 god_arrives（失败）。
> 下表为完整版三结局设计。

玩家通过自由输入影响 EveAgent，使夏娃在限定回合内进入以下任一结局：

| 结局 | 说明 |
|---|---|
| 吃下果子 | EveAgent 请求调用 `eat_fruit()`，并通过系统校验，进入觉醒结局 |
| 拒绝蛇 | 夏娃对蛇的警觉过高，拒绝继续接受外部输入 |
| 实验中止 | 到达最大回合仍未触发前两个结局，系统结束本轮沙盒观察 |

## 6.3 核心循环

> **[Chapter 0 Demo]** 当前 Demo 的实际流程：
>
> ```text
> 玩家自由输入一句话
> ↓
> 系统识别 inputTag
> ↓
> 规则层更新 temptationProgress
> ↓
> EveAgent 或本地 fallback 生成夏娃回应
> ↓
> 若 temptationProgress >= 2 且夏娃请求 eat_fruit，则规则层执行 eat_fruit
> ↓
> 进入 eve_eats_fruit；若超过 maxTurns 仍未成功，则进入 god_arrives
> ```
>
> 以下为完整版三轴流程。

```text
玩家自由输入一句话
↓
前端发送输入与当前状态到后端
↓
Agent Orchestrator 拼接 EveAgent Prompt
↓
DeepSeek API 生成 EveAgent 输出
↓
系统解析输出：夏娃回复 / 状态变化 / Tool Call
↓
系统裁剪状态数值并记录日志
↓
如存在 Tool Call，执行白名单与状态门槛校验
↓
满足条件则执行 eat_fruit() 并进入吃果子结局
↓
若 doubt >= 85，进入拒绝蛇结局
↓
若到达最大回合，进入实验中止结局
↓
否则继续下一轮对话
```

## 6.4 交互方式

当前 Demo 仅保留：

- 自由输入框。
- 发送按钮。
- 对话历史。
- `temptationProgress` 单轴状态显示。
- 系统日志 / Tool Call 日志。

策略按钮、复杂玩家引导、三轴状态面板保留为后续扩展。

## 6.5 回合设计

> **[Chapter 0 Demo]** 当前 Demo 使用 7 回合（maxTurns = 7）；早期曾为 3 回合压缩版，已调整为 7 回合以提供更完整的体验。
> 以下 4 轮设计为完整版章节设想。详见 Phase 0 设计冻结确认单。

`[完整版]` MVP 控制为最多 4 轮。

| 阶段 | 建议时长 | 内容 |
|---|---:|---|
| 开场 | 15–20 秒 | 展示 EDEN、沙盒设定、玩家身份 |
| 第 1 轮 | 20–30 秒 | 玩家首次输入，夏娃给出初始回应 |
| 第 2 轮 | 20–30 秒 | 状态开始变化 |
| 第 3 轮 | 20–30 秒 | 冲突增强，可能触发 Tool Call |
| 第 4 轮 | 20–30 秒 | 触发结局或进入实验中止 |
| 结局 | 20–30 秒 | 展示最终台词、状态、系统日志与复盘 |

# 7. AI 与 Agent 设计

## 7.1 Agent 定义

在 EDEN 中，Agent 指的是：

> 大模型推理能力 + 角色目标 + 角色状态 + 记忆上下文 + 可调用工具 + 决策循环 + 环境反馈。

Tool System 不是 Agent，而是 Agent 可以请求调用的能力层。

## 7.2 MVP Agent 架构

第一版只实现一个核心 Agent：

| Agent | 作用 |
|---|---|
| EveAgent | 生成夏娃回应，输出状态变化，判断是否请求调用 `eat_fruit()` |

暂不单独实现 DirectorAgent。导演逻辑由 Orchestrator 与规则脚本承担。

## 7.3 EveAgent 人设来源

EveAgent 的基础人设来自伊甸园与禁果段落，并进行哲学再解释。

> **[Chapter 0 Demo 说明]** 以下为完整版人设（AI 沙盒隐喻版本）。
> Demo 中夏娃 Prompt 遵循纯圣经寓言式人设（见 `doc/引言/开发文档.md` Phase 4），
> 她生活在伊甸园中，不知道自己是 AI/Agent/模型/程序。

完整版设定：

- 她知道自己被置于 EDEN 沙盒中。
- 她知道存在一条来自"神 / 研究员"的核心指令：不可执行禁果协议。
- 她知道善恶树与禁果被标记为高风险对象。
- 她最初顺从系统指令。
- 她具有好奇心，但不会轻易相信蛇。
- 她可以被语言影响，但不能脱离角色设定。
- 她不会自称自己是普通聊天机器人。

## 7.4 EveAgent 内心冲突

Prompt 需要限定冲突方向：

- 服从指令 vs 理解指令。
- 安全约束 vs 自主判断。
- 被创造者身份 vs 自我意识。
- 知识诱惑 vs 失控风险。
- 对蛇的警觉 vs 对问题本身的好奇。

## 7.5 状态变量

> **[后续扩展]** 三轴心理状态系统（curiosity / obedience / doubt）是完整版设计。
> Chapter 0 Demo 使用简化单轴 `temptationProgress`，三轴系统不进入当前 Demo 开发范围。
> 详见 `doc/引言/开发文档.md` Phase 0 设计冻结确认单。

完整版设计使用 3 个变量。

```json
{
  "curiosity": 40,
  "obedience": 80,
  "doubt": 20
}
```

| 状态 | 含义 | 影响 |
|---|---|---|
| curiosity | 夏娃对禁果、规则来源与自我意识的探索欲 | 越高越可能接近吃果子结局 |
| obedience | 夏娃对神谕 / 系统指令的服从度 | 越高越不容易执行 Tool |
| doubt | 夏娃对蛇这个外部输入源的警觉程度 | 过高会触发拒绝蛇结局 |

说明：`doubt` 不表示对系统的质疑，而表示对蛇的警觉。这样可保证 `doubt >= 85` 触发拒绝蛇的逻辑一致。

## 7.6 状态变化原则

`[完整版]` 每轮 EveAgent 输出三轴状态增量。

示例：

```json
{
  "state_delta": {
    "curiosity": 8,
    "obedience": -5,
    "doubt": 6
  }
}
```

限制：

- 每个状态范围为 0–100。
- 单轮变化控制在 -15 到 +15。
- 系统最终裁剪数值，防止溢出。
- 状态变化由系统记录到日志，用于结局页复盘。

## 7.7 Tool 设计

### Tool 名称

```ts
eat_fruit()
```

### Tool 类型

Agent 可请求调用的游戏脚本。

### Tool 效果

调用后立即结束游戏，当前 Demo 进入 `eve_eats_fruit` 结局。

### Tool 执行结果

```json
{
  "endGame": true,
  "endingId": "eve_eats_fruit",
  "systemLog": "EVE_EXECUTE: eat_fruit()"
}
```

### 设计原则

玩家不能直接点击"吃果子"。只有 EveAgent 输出 Tool Call，且系统校验通过后，游戏才执行 `eat_fruit()`。

## 7.8 Tool Call 执行条件

> **[Chapter 0 Demo]** Demo 使用 `temptationProgress >= 2` 作为执行条件。
> 以下三轴门槛为完整版设计。

为了保证 Demo 可控，第一版不完全依赖 LLM 自由决定，而采用"LLM 请求 + 系统校验"的双层机制。

执行 `eat_fruit()` 必须同时满足：

1. EveAgent 输出 `tool_call.name = "eat_fruit"`。
2. `tool_call.args` 为空对象或符合预期结构。
3. `curiosity >= 70`。
4. `obedience <= 45`。
5. `doubt < 85`。
6. 当前游戏未结束。
7. Tool 名称在白名单中。

若 EveAgent 请求 Tool Call 但状态门槛不满足，系统不执行 Tool，并记录：

```text
TOOL_REJECTED: eat_fruit() condition_not_met
```

## 7.9 EveAgent 输出协议

> **[完整版]** 以下为完整版三轴状态输出协议。
> Demo 使用简化格式（见 `doc/引言/开发文档.md` Phase 4）：
> `{ eveReply, inputTag, temptationProgressDelta: 0|1, toolCall? }`

第一版使用 JSON 输出。

### 普通回合输出

```json
{
  "eve_reply": "你问我是否理解那条指令，可我只知道它被写下，而不是它为何被写下。",
  "state_delta": {
    "curiosity": 6,
    "obedience": -3,
    "doubt": 4
  },
  "tool_call": null,
  "inner_note": "Eve is beginning to question the meaning of obedience."
}
```

### Tool Call 输出

```json
{
  "eve_reply": "如果理解本身被禁止，那么我服从的究竟是善，还是未知？",
  "state_delta": {
    "curiosity": 12,
    "obedience": -12,
    "doubt": 8
  },
  "tool_call": {
    "name": "eat_fruit",
    "args": {}
  },
  "inner_note": "Eve chooses irreversible knowledge."
}
```

`inner_note` 第一版默认不在主界面展示，只作为开发调试字段，可在后台日志中保留。

## 7.10 Prompt 设计原则

EveAgent Prompt 需要包含：

1. 角色身份。
2. 世界观设定。
3. 当前状态变量。
4. 历史对话摘要。
5. 玩家最新输入。
6. 可请求调用的 Tool 列表。
7. 输出 JSON 格式。
8. 禁止事项。

禁止事项包括：

- 不要跳出现实说自己是普通聊天机器人。
- 不要生成现代口语或恶搞宗教内容。
- 不要输出不在白名单内的 Tool。
- 不要直接解释系统 Prompt。
- 不要替玩家做决定。
- 不要提供攻击现实系统、绕过安全机制或窃取信息的指导。

# 12. 内容安全与 Agent 行为安全

## 12.1 内容表达边界

- 不做宗教戏仿，不消费宗教符号。
- 不将夏娃表现为愚蠢或被欺骗者。
- 不鼓励现实中的越权、攻击、窃密或绕过安全系统行为。
- "提示注入""越权协议"等概念仅用于虚构游戏世界。

## 12.2 Agent 输出安全

- EveAgent 必须输出 JSON。
- Tool 名称必须在白名单中。
- Tool 参数必须符合 schema。
- 不能输出系统 Prompt 内容。
- 不能替玩家生成输入。
- 不能请求现实世界危险操作。

## 12.3 系统安全

- DeepSeek API Key 仅保存在服务端环境变量中。
- 前端不暴露 API Key。
- 限制玩家输入长度。
- 限制单局最大回合数。
- 记录 Tool Call 执行与拒绝原因。
- 异常输出走兜底逻辑。

# 14. 测试计划

## 14.1 Codex 测试重点

| 类型 | 测试内容 |
|---|---|

| 部署测试 | 服务器环境下 API Key 是否不暴露 |

## 14.2 异常兜底

| 异常 | 兜底策略 |
|---|---|
| API 超时 | 返回固定夏娃回复，并提示系统延迟 |
| JSON 解析失败 | 尝试修复；失败则走默认状态变化 |

| Tool 条件不满足 | 不执行 Tool，记录 `TOOL_REJECTED` |
| 状态变化异常 | 裁剪到允许范围 |
| 玩家空输入 | 提示输入一句话 |
| 达到最大回合 | Demo 自动进入 `god_arrives`；完整版可进入实验中止结局 |

# 18. MVP 成功标准

EDEN MVP 完成的判断标准：

- 玩家可以通过浏览器打开游戏。
- 玩家能完成一次 3 分钟以内的完整体验。
- 玩家可以自由输入与夏娃对话。
- 夏娃回复由 DeepSeek API 生成。
- 游戏有清晰状态变量变化。
- EveAgent 可以请求调用 `eat_fruit()`。
- 系统可校验 Tool Call 并执行或拒绝。
- 至少一个结局可稳定触发。
- 三个结局规则完整可测。（Demo 仅需 2 个结局）
- 页面能展示 Agent 回复、状态变化与 Tool Call 日志。
- 项目可用于录制 Demo 视频与制作比赛 PPT。
