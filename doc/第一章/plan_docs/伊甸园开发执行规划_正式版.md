### Task 2.4：登录系统（用户名 + 密码自动注册）

- **任务描述**：实现用户名+密码自动注册登录系统，使用 Vercel KV 作为 Serverless 后端：
  1. **登录 API** `src/app/api/auth/route.ts`：
     - `POST` 请求接收 `{ username: string, password: string }`
     - 先查询 KV 中是否存在该用户名：
       - 不存在 -> 自动注册：存储 `{ username, passwordHash, createdAt }` 到 KV key `user:{username}`
       - 存在 -> 验证密码 hash 是否匹配
     - 验证成功 -> 生成简单 token（`username + timestamp` 的 base64，不用 JWT 库），存入 KV key `session:{token}` -> `{ username, expires }`（24h 过期）
     - 返回 `{ token, username, isNewUser }`
     - 密码错误 -> 返回 401 `{ error: "密码错误" }`
     - KV 不可用 -> 返回 `{ token: null, fallback: true }`（兜底：本地模式，不登录也能玩）
  2. **登录 UI** `src/components/world/LoginPanel.tsx`：
     - 首页右上角显示登录区域：未登录时显示用户名+密码输入框和「进入」按钮；已登录时显示用户名和「退出」按钮
     - 输入框有最小长度校验（用户名 >= 2 字符，密码 >= 4 字符）
     - 登录成功后显示欢迎文案
     - 兜底模式（KV 不可用）显示「游客模式」，不阻断游戏
  3. **Token 存储**：登录成功后 token 存入 localStorage key `eden:auth:token`
  4. **首页集成**：在 `src/app/page.tsx` 中集成 `<LoginPanel>` 组件
- **依据文档条目**：用户需求（仅实现「用户名+密码自动注册」逻辑，用 Serverless 云服务实现）；`AGENTS.md` Coding Rules（不硬编码密钥；AI 失败兜底）
- **开发时长**：2.5 小时
- **验收标准**：
  - 首页右上角出现登录区域
  - 输入新用户名+密码点击「进入」，自动注册并登录成功
  - 输入已存在用户名+正确密码，登录成功
  - 输入已存在用户名+错误密码，提示「密码错误」
  - 登录后显示用户名，可点击「退出」
  - KV 不可用时进入「游客模式」，不报错

- **注意事项**：不引入 JWT 库（用简单 base64 token + KV 校验）；不存储明文密码；真实 KV Token 只在环境变量中；**禁止修改** 首页核心布局，只追加登录区域

### Task 2.5：云端存档/图鉴同步

- **任务描述**：实现云端存档和图鉴同步功能，使用 Vercel KV：
  1. **云端存档 API** `src/app/api/cloud-save/route.ts`：
     - `POST` 请求接收 `{ token, state }`：校验 token -> 将 `state` 存入 KV key `save:{username}` -> 返回 `{ success: true }`
     - `GET` 请求接收 `token`：校验 token -> 从 KV 读取 `save:{username}` -> 返回 `{ state }` 或 `{ state: null }`
     - `POST` 请求接收 `{ token, achievements }`：将跨局成就数据存入 KV key `achievements:{username}`
     - `GET` 请求接收 `token` + `type=achievements`：读取跨局成就数据
     - token 无效 -> 返回 401；KV 不可用 -> 返回 `{ success: false, fallback: true }`
  2. **同步 hook** `src/hooks/useCloudSync.ts`：
     - `syncSave(state)`：登录状态下自动将存档推送到云端
     - `loadCloudSave()`：登录后从云端拉取存档
     - `syncAchievements(achievementData)`：将跨局成就推送到云端
     - `loadCloudAchievements()`：从云端拉取跨局成就
     - 未登录时所有函数为 no-op；KV 不可用时静默失败
  3. **自动同步时机**：
     - 登录成功后：自动拉取云端存档和成就
     - 每次手动存档时：自动推送存档到云端
     - 每次解锁新印记时：自动推送成就到云端
     - 结局复盘时：自动推送本局成就到云端
  4. **冲突处理**：云端有存档但本地无存档时，提示「发现云端存档，是否恢复」；本地有存档但云端无存档时，自动推送
- **依据文档条目**：用户需求（做云端存档/图鉴同步，用 Serverless 云服务实现）；`AGENTS.md` Coding Rules（AI 失败兜底；保持浏览器端可部署）
- **开发时长**：2.5 小时
- **验收标准**：
  - 登录后自动从云端拉取存档和成就
  - 手动存档时自动同步到云端
  - 解锁新印记时自动同步成就到云端
  - 未登录时同步功能为 no-op，不影响本地游戏
  - KV 不可用时同步静默失败，不报错
  - 云端有存档时提示恢复
  - 换设备登录后可恢复云端存档和成就
  - `npm run lint` + `npx tsc --noEmit` + `npm run build` 通过
- **注意事项**：云端存档数据格式与本地 localStorage 格式一致（不额外转换）；**禁止修改** 现有 localStorage 存档逻辑（云端是叠加同步，不替代本地）；同步失败不阻断游戏；不存储敏感信息到云端

## 9. CodeBuddy 执行要求

### 9.1 执行流程

1. **每个 Phase 开始前**：在 CodeBuddy 中创建新对话，引用本规划文档，声明当前 Phase
2. **每个 Task 执行前**：在对话中引用 Task 编号和验收标准
3. **每个 Task 完成后**：在对话中记录完成情况，截图验证结果
4. **每个 Phase 结束后**：输出 Phase 完成报告（模板见 9.2）
5. **全部完成后**：输出最终完成报告，更新 `docs/PROJECT_CONTEXT.md`

### 9.2 Phase 完成报告模板

```text
## Phase X 完成报告

### 执行任务
- Task X.1：[完成/部分完成/未完成]
- Task X.2：[完成/部分完成/未完成]

### 验证结果
- npm run lint: [pass/fail]
- npx tsc --noEmit: [pass/fail]
- npm run build: [pass/fail]
- 冒烟测试: [pass/fail]
- e2e: [pass/fail]

### 人工确认
- [截图1]：...
- [截图2]：...

### 未完成项和风险
- ...

### CodeBuddy 证据链
- 本轮对话已保留：[是/否]
- 核心设计决策：...
- 主要调试记录：...
```

### 9.3 禁止事项

- 禁止一次性重写全部模块，必须逐 Task 执行
- 禁止修改本规划文档未提及的现有文件（除非 Task 明确要求）
- 禁止跳过验收标准中的任何一项
- 禁止在未完成 lint/tsc/build 验证的情况下声明 Task 完成
- 禁止删除/修改 `doc/` 目录下任何原有文件
- 禁止将 Codex 记录为核心开发工具
