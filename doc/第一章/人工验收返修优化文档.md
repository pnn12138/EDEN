# EDEN 第一章人工验收返修优化文档

版本：v1.0  
日期：2026-06-23  
用途：根据人工验收截图与玩家反馈，指导 CodeBuddy 完成第一章 `/world` 最后一轮体验返修  
范围：NPC 输出、行动点与轮次一致性、对话框布局、属性/线索/行动/低语信息架构、成就入口

---

## 1. 总体判断

当前第一章机制已经具备可玩性：12 时段、行动点、场景互动、园中回响、园中印记、神的注视、禁忌动作链和结局复盘都已落地。

但人工验收截图暴露出几个会显著影响试玩观感的问题：

1. NPC 回复出现原始 JSON，破坏沉浸感，属于必须修复的阻断问题。
2. 不同地点/对话状态下轮次与行动点显示不一致，说明状态同步与推进规则仍不够清晰。
3. 行动点规则和用户预期不一致：玩家希望每轮 5 AP，NPC 每轮最多 3 次成功工具调用；轮次必须由玩家主动进入下一轮。
4. 对话框信息架构不清晰：推荐低语、可见角色、属性、线索、可行动作的位置需要重排。
5. 成就入口没有按需求放在顶部地图旁的小图标中，而只是作为对话框 Tab，展示感不足。

本轮返修目标：

```text
保留现有机制深度，
修掉破坏体验的问题，
让玩家一眼看懂这一轮还能做什么、谁在场、能对谁说话、有哪些行动、成就在哪里。
```

## 2. P0 阻断：NPC 回复 JSON 泄露

### 2.1 问题表现

截图中，女人和亚当的回复出现类似：

```json
{"eveReply":"我听见了你的声音。可我仍然记得祂说不可吃。你说的这些，让我开始思考为什么。","inputTag":"tempt_wisdom",...}
```

这是严重沉浸破坏。玩家不应看到任何 JSON、字段名、内部标签或工具结构。

### 2.2 可能原因

1. 世界 NPC Agent 期望纯文本，但模型沿用 Chapter 0 的 JSON 输出格式。
2. `sanitizeWorldReply` / `naturalizeNpcReply` 没有识别 JSON 字符串并提取 `eveReply` / `reply` / `visibleReply`。
3. 某些 fallback 或历史对话把 JSON 原样推入对话流。
4. 亚当 Agent 或 World Agent 仍可能返回 `eveReply` 字段名。

### 2.3 修复要求

所有世界 NPC 输出进入 UI 前必须经过统一清洗：

```text
raw model output
↓
detect JSON / JSON-like string
↓
extract visible text field
↓
remove engineering terms
↓
role-specific naturalization
↓
if still invalid -> local fallback
```

建议增强：

```text
src/agents/common/naturalizeNpcReply.ts
src/agents/world/worldAgentPrompts.ts
src/app/api/world/route.ts
src/agents/adam/buildAdamPrompt.ts
```

清洗优先级：

```text
visibleReply
reply
eveReply
adamReply
text
content
```

如果 JSON 解析失败但文本明显包含字段片段，也要用正则兜底提取：

```text
"eveReply":"..."
"visibleReply":"..."
"reply":"..."
```

若无法提取，使用角色 fallback，不得原样展示。

### 2.4 禁止玩家可见内容

玩家可见文本不得出现：

```text
JSON
eveReply
inputTag
toolCall
progressDelta
null
Agent
模型
系统
规则层
API
```

## 3. P0 阻断：轮次与行动点统一

### 3.1 当前问题

用户反馈：

```text
不同位置居然出现了不同的轮次与不同的剩余行动点次数。
```

这会让玩家误以为每个地点有独立轮次或独立 AP。第一章必须只有一个全局世界时段和一个全局玩家行动点池。

### 3.2 最终规则

全局状态唯一：

```ts
timeSlot: 1..12
dayIndex: 1..6
timeOfDay: "day" | "night"
playerActionPoints: 0..5
npcActionBudget: 0..3
```

玩家每轮：

```text
玩家 AP = 5
```

NPC 每轮：

```text
NPC 成功调用工具次数上限 = 3
```

注意：NPC AP 不是给每个 NPC 各 3 点，而是世界结算阶段总共最多成功执行 3 个 NPC 工具/事件，避免失控。

### 3.3 不再自动进入下一轮

新规则：

```text
玩家消耗 AP 到 0 后，不自动进入下一轮。
玩家只是不能继续消耗 AP 的行动。
只有玩家点击顶部“进入下一轮”按钮，才推进 timeSlot。
进入下一轮后恢复玩家 AP 到 5，并刷新昼夜。
```

原因：

* 玩家需要看清本轮发生了什么。
* 玩家需要主动承担“推进时间”的决策。
* 避免 AP 用尽后突然跳转昼夜导致困惑。

### 3.4 UI 表现

顶部显示：

```text
时段 5/12 · 第三日 白天
神的注视：●●○○
行动：●●●○○
[进入下一轮]
```

神的注视与行动点都可以用点状表现，但必须视觉区分：

| 指标 | 样式建议 |
| --- | --- |
| 神的注视 | 冷白 / 淡金 / 更尖锐，满点有压迫感 |
| 行动点 | 绿色 / 暖绿 / 更柔和，已消耗为空心 |

行动点：

```text
剩余 AP = 实心点
已消耗 AP = 空心点
```

按钮：

```text
进入下一轮
```

始终放在顶部地图按钮附近，或者紧邻行动点。玩家任何时候都可以主动进入下一轮，但点击前需确认：

```text
结束这一轮，进入下一时段？
```

## 4. P1：同一 NPC 每轮对话次数

### 4.1 当前规则问题

当前同一时段同一 NPC 只能低语一次。用户希望调高：

```text
每一轮跟同一个 NPC 对话次数最多完成三次。
```

### 4.2 新规则

每轮：

```text
同一 NPC 最多成功对话 3 次
对女人核心低语也最多 3 次
每次低语消耗 1 AP
```

注意：

* “最多完成三次”指成功调用并产生回复的次数。
* 空输入、API 失败 fallback 可继续按一次行动处理，但不要增加成功对话次数，避免玩家被异常惩罚。
* 如果 AP 不足，则不能继续低语。

建议状态从数组改为计数：

```ts
actionsThisSlot: {
  whisperedNpcCounts: Record<EdenNpcId, number>;
  sceneActionIds: string[];
  usedItemIds: string[];
  womanCoreWhisperCount: number;
};
```

若为降低改动量，也可以保留数组，另加：

```ts
whisperCountsThisSlot: Record<EdenNpcId, number>
```

## 5. P1：对话框默认大小与布局

### 5.1 当前问题

截图中对话框默认太宽、右侧占用过大，压迫主场景；底部输入框与右侧对话框之间的信息关系也不清楚。

### 5.2 默认尺寸建议

桌面默认：

```text
宽度：420-480px
高度：68vh 左右
最大宽度：min(480px, 32vw)
最小宽度：380px
```

仍可拖动与拉伸，但首次打开不要覆盖太多画面。

### 5.3 对话 Tab 信息顺序

对话 Tab 应只放“对话相关内容”，顺序如下：

```text
1. 可尝试低语
2. 对话历史
3. 当前输入提示 / 当前对象
```

“可尝试低语”不要放在对话历史上方太远，也不要藏在其它面板中。它应出现在底部输入框上方，类似截图 3 所示位置，让玩家输入前就能看到。

建议布局：

```text
对话历史滚动区
↓
可尝试低语横向/纵向短列表
↓
输入框 + 发送按钮
```

如果保留底部全局输入条，则推荐低语应靠近该输入条，而不是只在浮窗顶部。

## 6. P1：属性、可见对象、线索、可行动作重排

### 6.1 “此处可见”移动到属性部分

当前“此处可见”不应散落在对话区或地图细节里。它应作为属性 Tab 的顶部模块。

属性 Tab 顶部：

```text
此处可见：
[女人] [亚当] [刺猬] [狐狸] ...
```

玩家点击不同角色 chip 后，属性面板显示该角色资料：

```text
名称
身份/气质
当前位置
对蛇态度
当前意图
可低语 / 不可低语
```

这也满足用户需求：

```text
属性的顶部可以选择不同的角色查看属性。
```

### 6.2 可行动作放在线索下面

信息架构建议：

```text
属性 Tab：
- 此处可见
- 当前选中角色属性
- 场景状态

线索 Tab：
- 已发现线索
- 园中回响
- 可行动作
```

“可行动作”放在线索下面，因为它们本质上是基于当前地点和已知信息产生的可操作项。

### 6.3 对话 Tab 不放可行动作

对话 Tab 聚焦：

* 当前对象。
* 对话历史。
* 推荐低语。
* 输入。

不要把“循水声”“拨开落叶”等场景动作放在对话 Tab 中，避免玩家误以为它们是对话选项。

## 7. P1：顶部成就入口

### 7.1 当前问题

用户明确要求：

```text
顶部地图旁边有一个小图标，点击打开成就界面。
```

当前“园中印记”作为对话框 Tab 不够明显，不符合需求。

### 7.2 修复要求

顶部按钮区：

```text
[神的注视点] [行动点] [进入下一轮] [地图] [园中印记图标] [收起对话框]
```

园中印记图标建议：

```text
✦
```

或使用已有图标库时用奖章/星标/印记类 icon。

点击后打开独立浮窗或侧栏：

```text
园中印记
主线印记
行为印记
园中异闻
```

不要只切换对话框 Tab。成就界面应该可以在对话框关闭时独立打开。

## 9. CodeBuddy 实施顺序

### Step 1：修 NPC JSON 泄露

优先级最高。完成后先单独验证：

* 女人回复不出现 JSON。
* 亚当回复不出现 JSON。
* 其它 NPC 回复不出现字段名。

### Step 2：统一全局轮次与 AP

* 玩家 AP 改为 5。
* AP 用尽不自动推进。
* 顶部新增“进入下一轮”按钮。
* 点击按钮才推进时段和昼夜，并补满 AP。
* 所有地点、对话框、属性面板只读同一个全局 state。

### Step 3：同 NPC 每轮对话上限改为 3

* 同一 NPC 成功对话计数。
* 达到 3 次后显示自然提示：

```text
这一轮你已经对他说得太多。等风换一个方向，再回来。
```

女人可用：

```text
她已经听得太久了。再说下去，只会让她退回沉默。
```

### Step 4：重排对话框信息架构

* 默认宽度缩小。
* 可尝试低语移动到输入框上方。
* 此处可见移动到属性 Tab 顶部。
* 属性 Tab 顶部可切换角色。
* 可行动作移动到线索下面。

### Step 5：顶部成就入口

* 地图按钮旁新增“园中印记”小图标。
* 点击打开独立成就界面。
* 对话框 Tab 中可保留入口，但不能是唯一入口。

### Step 6：复验与重启服务器

* `npm run lint`
* `npm run build`
* `npx tsc --noEmit`
* `node scripts/test-world-visual-smoke.mjs`
* 生产预览下 `node scripts/test-world-smoke.mjs <url>`
* 重启本地服务器，输出 `/world` 人工检验地址。

## 10. 验收标准

### 10.1 必须通过

* NPC 回复无 JSON、无字段名、无工程词。
* 全局时段和 AP 在所有地点保持一致。
* 玩家每轮 5 AP。
* NPC 每轮最多 3 次成功工具调用。
* AP 用尽不自动推进。
* 顶部有“进入下一轮”按钮，点击后才推进时段并切换白天/夜晚。
* 同一 NPC 每轮最多成功对话 3 次。
* 对话框默认宽度明显缩小。
* 可尝试低语在输入框上方。
* 属性 Tab 顶部有“此处可见”和角色切换。
* 可行动作位于线索下面。
* 顶部地图旁有“园中印记”小图标，并能打开成就界面。

### 10.2 不允许回归

* 园中树林白天/夜晚出现天使。
* 玩家可见“夏娃”。
* 玩家直接调用禁忌动作链。
* 信物直接触发吃果。
* Chapter 0 被破坏。
* 前端直接改 AP、时段或结局。
