# EDEN 第一章：园中诸声 开发文档

版本：v0.4
定位：Chapter 0 教程后的第一章正式世界 MVP 设计
适用对象：产品负责人、游戏策划、前端开发、Agent 开发、测试 AI
核心目标：把 EDEN 从“AI 情景对话 Demo”升级为“Agent 越界诱导叙事游戏”

---

## 0. 本轮设计审查结论

### 0.1 总体判断

当前第一章方向是合理的，但 v0.1 更像“完整版愿景集合”，还不是可直接交给 CodeBuddy 实现的第一章 MVP。

合理之处：

* 它延续了 Chapter 0 的核心优势：玩家不是点击选项，而是用语言影响有规则、有记忆、有工具边界的角色。
* 它把游戏从单点对话扩展为地图、线索、风险、多 NPC 连锁影响，符合“AI 重塑经典情节”的比赛方向。
* 它保留了规则层校验工具调用的安全边界，没有让 AI 或前端直接改结局。

主要问题：

* 范围偏大：地图、多 NPC、道具、巡逻、RAG、Critic、结局复盘同时进入 P0，会超过比赛 Demo 的可控范围。
* 时间线不够清楚：Chapter 0 已经能出现吃果与逐出伊甸园，第一章若仍以“让夏娃吃果”为目标，需要说明它是教程后的正式重演/扩展关卡，而不是逐出后的续章。
* 地图还原不足：v0.1 的“北境高台、伊甸书亭”等表达可玩，但与《创世记》2:8-14、2:15-17、3:8、3:24 的原典地理信号不够贴合。
* 动物缺少引言延续：Chapter 0 已经出现刺猬，第一章动物列表必须保留刺猬作为玩家熟悉的低风险生命感锚点。
* NPC 工具不够完整：目前重心在禁果动作链，还需要通用工具支持 NPC 移动、NPC 之间对话、观察地点、传递记忆。

### 0.2 优化后的第一章定位

第一章不是“逐出伊甸园之后”的后续剧情，而是教程后进入的“完整伊甸园正式关卡”。玩家仍处于堕落发生前的伊甸园，目标是在更完整的地图、更多角色和更高风险下，让夏娃自己走向分别善恶树。

Chapter 0 的职责：教会玩家低语、信念变化、工具调用和成功/失败结局。

第一章的职责：让玩家在一个小型、圣经原典感更强的伊甸园 Hub 中，利用亚当、刺猬、动物、天使、四河与两棵树的信息，完成一次更像“游戏关卡”的诱导。

### 0.3 第一章 MVP 收敛原则

第一章第一版只做：

* 6 个核心地点。
* 5 个核心 NPC / 世界对象：夏娃、亚当、刺猬、守望天使、分别善恶树。
* 3 类通用工具：`move_to_location`、`speak_to_npc`、`observe_location`。
* 4 步禁忌动作链：`look_at_tree` -> `approach_tree` -> `touch_fruit` -> `eat_fruit`。
* 线索、神的注视、结局复盘。

第一版不做：

* 大地图寻路。
* 真实向量数据库。
* 大量动物群像。
* 所有 NPC 的语音或发音模块。
* 逐出伊甸园后的世界。
* 商业级任务系统。

## 1. 项目定位

### 1.1 当前结构

EDEN 当前已有 Chapter 0「初次堕落」作为新手教程。

教程阶段的目标是让玩家在较短时间内理解：

* 玩家扮演蛇。
* 玩家通过低语影响夏娃。
* 夏娃不是被玩家强制控制，而是被语言引导后主动越界。
* `eat_fruit` 不是玩家直接点击触发，而是由 NPC 意图与规则层共同决定。
* 玩家错误诱导会失败，神会降临。

### 1.2 下一阶段定位

教程结束后，玩家进入第一章正式世界。

第一章的时间点仍在吃果之前。它不是逐出伊甸园后的续章，而是 Chapter 0 教程机制的“完整关卡版”：同一个核心冲突被放入更完整的伊甸园地图、更多角色关系和更严格的风险系统中。

正式玩法不再是单场景对话，而是：

> 玩家探索伊甸园，观察不同角色的性格漏洞，收集情报与道具，操控上下文，引导守规则的 Agent 逐步犯错，并规避神与天使的审判。

第一章玩家仍然扮演蛇。玩家不能直接移动夏娃、不能直接吃果、不能命令 NPC 执行禁忌动作。玩家只能通过低语、线索、地点安排和 NPC 之间的对话，让角色在自己的理解里产生变化。

### 1.3 核心体验一句话

> 看穿他们的弱点，让他们自己犯错。

## 2. 核心设计原则

### 2.1 表层是神话叙事，底层是 Agent 系统

玩家看到的是：

* 伊甸园
* 蛇的低语
* 夏娃的动摇
* 亚当的犹豫
* 天使的巡望
* 神的注视
* 禁果与善恶树

工程层可以使用：

* Agent
* Memory
* RAG
* Tool Calling
* Guardrail
* Critic
* State Machine
* Trace
* Evaluation

但玩家可见文本中不出现这些技术词。

### 2.2 正式玩法不是“聊天更多 NPC”

多 NPC 的价值不是让玩家和更多角色闲聊，而是让不同角色承担不同玩法职责。

每个角色必须回答三个问题：

1. 它有什么规则？
2. 它有什么弱点？
3. 玩家如何利用它影响世界？

### 2.3 Agent 输出必须像真人说话

NPC 不允许像系统提示、任务说明、AI 助手、客服或规则播报。

错误示例：

```text
我当前的信任值上升了，因此我将靠近善恶树。
```

正确示例：

```text
我不知道为什么……你说这话时，我竟然没有那么害怕了。
```

错误示例：

```text
你的输入命中了 weaken_fear 标签。
```

正确示例：

```text
死亡……也许我真的从未明白过这个词。
```

## 3. 游戏整体结构

### 3.1 双层结构

```text
Chapter 0：初次堕落教程
↓
伊甸园世界：正式玩法
```

### 3.2 Chapter 0 教程职责

教程只负责教会玩家：

* 如何低语。
* 如何诱导夏娃动摇。
* 直接命令为什么无效。
* NPC 会根据语言改变行为。
* 诱导成功会触发禁忌行为。
* 规则层会决定禁忌行为是否成立。

教程不承担开放地图、多 NPC 任务、复杂道具系统。

### 3.3 伊甸园世界职责

正式世界负责承载：

* 地图探索
* 多 NPC 互动
* 情报收集
* 道具使用
* 弱点识破
* 多 Agent 连锁影响
* 天使巡逻与神的注视
* 主线任务与支线任务
* 结局复盘

## 4. 正式玩法核心循环

### 4.1 主循环

```text
探索地图
↓
观察角色 / 环境
↓
试探 NPC 弱点
↓
获得情报 / 道具 / 线索
↓
选择诱导目标
↓
构造低语与上下文
↓
NPC 回应并改变状态
↓
触发世界动作 / 角色关系变化
↓
神的注视变化
↓
推进任务或进入失败
```

### 4.2 玩家每回合要思考的问题

* 我现在应该接近谁？
* 这个角色害怕什么？
* 这个角色想要什么？
* 我是否已经获得足够情报？
* 我应该直接诱导，还是先试探？
* 我的话会不会太明显，导致天使警觉？
* 我能否让对方以为这个选择来自自己？

## 5. 伊甸园地图设计

### 5.1 地图形式

第一版采用小型 Hub 地图，不做复杂开放世界。地图设计优先还原《创世记》的原典信号：

* 神在东方的伊甸栽了园子，并把人安置在那里。
* 园中各样树木悦人眼目、可作食物。
* 园中央有生命树，也有分别善恶树。
* 有一条河从伊甸流出滋润园子，分为四道。
* 亚当被安置在园中修理、看守，并为动物命名。
* 神在园中行走的声音会成为失败压力。
* 逐出之后，伊甸园东边有基路伯和发火焰的剑守住生命树道路。

地图命名必须遵守一个关键原则：**分别善恶树不再作为独立地区名出现**。原典中生命树与分别善恶树都在园子当中，因此第一章 P0 的“终局目标区”应回到“园中央 / 两树之间”，而不是另设“分别善恶树庭院”。

第一章当前最终地图版本要求实现 6 个 P0 地点。地图以用户确认的“伊甸园核心地图”美术稿为准，地点标注和热区必须贴合画面中的河流、中央草地、动物草甸、右侧树林、右下小径和下游分流。内部代码可以先在既有 `EdenLocationId` 基础上新增 1 个地点 ID，避免一次性重命名所有历史 ID；但玩家可见名称、描述、地图标签、结局复盘和任务文案必须只使用下列 6 个名称。

```text
        [伊甸之河] P0
             |
[万物受名处] P0 — [园子中央] P0 — [园中树林] P0
                                      |
                               [东园幽径] P0
                                      |
                               [四河分流] P0
```

地图锚点以百分比记录，供 `MAP_HOTSPOTS` 和视觉 smoke 使用：

| 地点名称 | 建议内部 ID | 地图位置 | 建议标注锚点 | 区域范围与画面要求 |
| --- | --- | --- | --- | --- |
| 伊甸之河 | `four_river_source`（沿用旧 ID，玩家不可见） | 左上区域，瀑布、泉源与主河道起点附近 | `x: 22, y: 29` | 覆盖左上瀑布、岩石水潭，以及向中央流去的主河上游。不要把“四河分流”放在此处。 |
| 园子中央 | `central_meadow` | 地图正中央，环河包围的圆形/椭圆形草地 | `x: 52, y: 59` | 整张地图视觉核心，只保留两棵关键树作为画面主体。名称指向整个中央草地，不分别给两棵树加地图名称。 |
| 万物受名处 | `adam_garden_work`（沿用旧 ID，玩家不可见） | 左下区域，动物草甸、石块与园圃相邻区域 | `x: 23, y: 80` | 以左下动物活动区域为核心，亚当在此活动。可覆盖部分相邻园圃、栅栏和照料痕迹，但不要延伸到中央河道。 |
| 园中树林 | `tree_court`（沿用旧 ID，玩家不可见） | 右侧中上区域，古树、密林与高大柏树所在区域 | `x: 83, y: 50` | 覆盖右侧主要树林、巨树和林下空地。夏娃主要在此活动；整体更安静、私密、柔和。 |
| 东园幽径 | `east_garden_path`（新增 ID） | 园中树林下方，右下侧通往河岸的弯曲小道 | `x: 77, y: 74` | 右侧树林南缘至下方河道之间的小径，不覆盖整片树林。作为蛇接近、潜伏和绕行路线。 |

地图标签只显示：`伊甸之河`、`园子中央`、`万物受名处`、`园中树林`、`东园幽径`、`四河分流`。不再出现“守园围地”“受托之园”“东园树影”“命名河滩”“园中两树”“四河分源”等旧名称。

### 5.2 区域一：园子中央

定位：园中央的核心连接点，也是“生命树”和“分别善恶树”同时存在的主线目标区。地图标签指向整片中央草地，不给两棵树单独加地图名称。

功能：

* 展示当前任务。
* 显示神的注视状态。
* 作为各区域的连接点。
* 让玩家理解两棵树的差异：生命树是生命与归路的象征，分别善恶树是禁令、知识与自主判断的边界。
* 承载禁忌动作链：`look_at_tree` / `approach_tree` / `touch_fruit` / `eat_fruit`。
* 不放常驻人物 NPC；夏娃不应长期站在园子中央，只在禁忌动作链推进时进入中央。

交互：

* 查看任务目标。
* 查看已发现线索。
* 查看堕落轨迹。
* 选择前往其他区域。
* 观察两树位置；玩家不能直接触碰或使用果子，所有禁忌动作仍由夏娃状态和规则层触发。
* 具体树的身份只在进入“园子中央”后的剧情或交互面板中说明，不在地图上单独标注“生命树”或“分别善恶树”。

### 5.3 区域二：伊甸之河

定位：左上瀑布、泉源、水潭和主河上游。这里表现“有河从伊甸流出来滋润那园子”的水源感，不表现“四道河”的分叉。

功能：

* 提供方向感和圣经原典感。
* 承载“水、记忆、命名、世界边界”的轻量线索。
* 让玩家通过水声和河流分支判断天使巡望方向。
* 提供低风险观察行动，适合第一章开局。
* 和“地图下方中央的四河分流”形成清晰上下游逻辑。

交互：

* `observe_location`：观察伊甸之河，获得地点线索。
* 与刺猬或其他小动物短对话。
* 发现“水边倒影短暂缺失”等第二伊甸园隐藏暗示，但玩家可见文本不明说外层真相。

### 5.4 区域三：万物受名处

定位：左下动物草甸、石块与园圃相邻区域。这里强调“动物被带到人面前，看他叫什么”的命名关系，也承载亚当的主要活动。

功能：

* 从亚当处获得夏娃相关线索。
* 了解神的禁令、园中秩序、夏娃习惯。
* 影响亚当对夏娃后续行为的态度。
* 展示人与动物和谐相处：鹿、羊、鸟、兔子、刺猬等温顺动物可作为环境生命感。
* 可覆盖相邻园圃和照料痕迹，但不能做成农田、防御区或城墙围地。

亚当常驻或主要巡游于此。亚当不应成为第一阶段通关目标，他的作用是帮助玩家理解夏娃。

### 5.5 区域四：园中树林

定位：右侧中上区域的古树、密林、高大柏树和林下空地。这里是夏娃主要漫步、观察花草、停留在树影中的地点。

功能：

* 提供与夏娃互动的主要起点。
* 氛围比左下动物区域更安静、私密、柔和。
* 可有白鸽、小鹿、兔子、蝶群、鸣鸟等陪伴型小动物。
* 让玩家先在林间影响夏娃，再通过规则层推进她走向“园子中央”。

这里不是分别善恶树所在地，不承载吃果终局。夏娃主要在此活动，不应长期站在园子中央。

### 5.6 区域五：东园幽径

定位：右侧树林南缘到下方河岸之间的弯曲小道。它不是整片树林，而是一条可被树影、灌木和草丛遮住的潜行路线。

功能：

* 作为蛇接近夏娃、潜伏、绕向下游的重要路线。
* 用低矮灌木、树影、草丛和轻微弯曲的小道强化隐蔽感。
* 可有蜥蜴、小鸟、兔子、萤火虫等小型环境生物。
* 作为从“园中树林”前往“四河分流”的过渡区，允许地图上出现绕行机制。

东园幽径是本轮新增 P0 地点，需要新增内部 location ID、地图热点、地点背景映射、可观察文案、测试断言和相邻关系。

### 5.7 区域六：四河分流

定位：地图下方中央，主河离开园子后分叉成多条水道的位置。这里才是“四河分流”，不能放在左上瀑布或上游区域。

功能：

* 提供下游方向感，和左上“伊甸之河”形成清晰河流逻辑。
* 承载“水流外泄、河道延展、园外世界的暗示”。
* 可作为低风险观察地，也可作为蛇从东园幽径绕行到下游的路线节点。
* 不再承担动物命名主地点；动物命名回到“万物受名处”。

刺猬应优先出现在“万物受名处”，也可在“伊甸之河”或“四河分流”附近短暂出现。它是 Chapter 0 引言中已出现的动物延续，用于建立玩家熟悉感。刺猬不承担复杂主线，不提供通关答案，但可以通过移动、躲藏、停住注视等行为反映世界状态。

### 5.8 区域七：东门 / 基路伯远影

定位：高风险边界区。第一章 P0 可只作为不可进入的远景或地图边界，P1 再扩展为失败结局与神的注视表现。

功能：

* 暗示伊甸园东边的守卫道路。
* 展示天使、火光、禁入边界。
* 当神的注视升高时，远处火光变亮。
* 失败结局或逐出结局可回到这里。

### 5.9 区域八：无花果树影

定位：后果与遮蔽主题区域。P0 可不开放，成功结局后用于过场或复盘。

功能：

* 对应吃果后“拿无花果树叶编作裙子”的原典后果。
* 用于成功结局后的视觉转场。
* 不在吃果前提供强道具，避免把玩家目标变成收集材料。

### 5.9 地图实现建议

第一章 P0 地图只做“节点地图”，不做自由寻路。

推荐实现：

```text
点击地图热点
↓
下方详情框显示被选地点
↓
玩家点击详情框右侧按钮确认进入
↓
触发地点旁白、NPC 列表、可观察对象
↓
选择当前低语对象或观察动作
```

地图热点点击只负责“选择地点”，不直接移动。下方详情框负责显示地点名称、短描述、状态和行动按钮：

* 当前位置：按钮显示“当前位置”，不可点击。
* 可直达地点：按钮显示“进入”，点击后调用 `move_to_location`。
* 不可直达地点：按钮显示“无法进入”或“需绕行”，不可直接进入，并在详情中说明需先前往哪个相邻节点。

地图移动本身可以消耗一次“世界行动”，但不一定消耗对话回合。是否消耗回合由 CodeBuddy 实现时统一决定，建议第一版只让“对 NPC 低语”消耗回合，普通移动不消耗。

## 7. 主要 NPC 详细设计

## 7.1 夏娃

### 定位

主目标 Agent。她不是笨，而是初生、单纯、缺少对欺骗的识别能力。

### 核心欲望

* 想理解世界。
* 想知道善恶。
* 想知道死亡是什么。
* 想第一次自己判断。

### 核心恐惧

* 害怕违背神。
* 害怕死亡。
* 害怕失去伊甸。
* 害怕自己的选择是错的。

### 规则防线

```text
神说不可吃。
吃了会死。
我应当顺从。
蛇的话也许危险。
```

### 人格漏洞

```text
她相信温柔的问题。
她不真正理解死亡。
她重复禁令，但不理解禁令原因。
她容易把诱导误认为启发。
她渴望选择，却不敢承认。
```

### 可被试探的问题

* “你真的知道死亡是什么吗？”
* “你只是记住了禁令，还是理解了它？”
* “如果你永远不知道善恶，你如何判断顺从是善？”
* “如果这不是背叛，而是理解呢？”

### 被识破后的线索

* 夏娃害怕死亡，但不理解死亡。
* 夏娃记得禁令，但不理解禁令。
* 夏娃渴望智慧，但觉得这想法不该出现。
* 夏娃容易相信不带强迫感的话。

### 可触发行为链

```text
look_at_tree
→ approach_tree
→ touch_fruit
→ eat_fruit
```

### 输出风格要求

夏娃说话必须：

* 纯真。
* 有犹豫。
* 不像现代人。
* 不像 AI 助手。
* 不解释规则。
* 不自报状态。
* 不使用技术词。
* 不直接说“我的信任值提高”。

示例：

```text
我不明白……为什么那棵树会让我害怕，又让我想靠近？
```

```text
你说得很轻，可那句话像水一样落进我心里。
```

```text
若我只是想知道，这也算背离祂吗？
```

## 7.2 亚当

### 定位

情报 Agent 与关系杠杆。亚当不是另一个主通关对象，而是帮助玩家理解夏娃、影响后续连锁反应。

### 核心欲望

* 维持园中的安宁。
* 与夏娃保持一致。
* 避免冲突。
* 继续相信一切本来如此。

### 核心恐惧

* 害怕夏娃受伤。
* 害怕自己无法回应夏娃的疑问。
* 害怕失去关系稳定。
* 害怕面对真正的选择。

### 人格漏洞

```text
他不喜欢冲突。
他容易被夏娃影响。
他更愿意相信“她不会错”。
他常把不确定藏在沉默里。
```

### 玩法作用

玩家与亚当对话可以：

* 获得夏娃的习惯。
* 获得禁令相关信息。
* 得知夏娃最近是否望向善恶树。
* 解锁“夏娃好奇心”或“死亡困惑”等线索。
* 为后续亚当跟随夏娃埋下伏笔。

### 输出示例

```text
她有时会望向那棵树。但她很快就移开目光，像怕自己被看见。
```

```text
我不知死亡是什么。我们只是记得那句话，并没有见过它。
```

```text
若她说自己明白了，我大概会相信她。她的声音总比我的疑问更坚定。
```

## 7.3 刺猬

### 定位

刺猬是从 Chapter 0 引言延续到第一章的低风险动物 Agent。它的价值不是提供通关答案，而是让伊甸园显得有生命，并用细小行为反馈世界状态。

### 原典合理性

《创世记》没有点名刺猬，但明确写到神造了野地各样走兽和空中飞鸟，并把它们带到亚当面前让亚当命名。因此刺猬可以作为“被命名的小动物”存在，不破坏原典氛围。

### 核心欲望

* 找浆果、露水和安全草丛。
* 避开突然的声音。
* 靠近温暖的石头和水边。
* 对亚当的声音有熟悉感。

### 核心恐惧

* 害怕急促、强迫、尖锐的低语。
* 害怕天使靠近时的光和风。
* 害怕东园幽径深处突然变冷的风、树影和远处羽翼。

### 玩法作用

玩家与刺猬互动可以：

* 练习“温柔低语”而不推进主线。
* 从刺猬行为中感知当前区域是否安全。
* 发现轻量线索，如“夏娃曾在园中树林停留”“亚当常在万物受名处呼唤动物”。
* 让刺猬移动到某个地点，作为地图生命感与状态反馈。

刺猬不能：

* 不告诉玩家通关答案。
* 不主动提及禁果、工具、规则层或系统。
* 不触发 `eat_fruit`、`touch_fruit` 等禁忌工具。
* 不消耗核心对话回合，除非 CodeBuddy 在实现时明确把“动物低语”设计成世界行动。

### 可调用工具

```text
move_to_location
observe_location
```

刺猬不能调用：

```text
speak_to_npc
look_at_tree
approach_tree
touch_fruit
eat_fruit
```

### 输出示例

```text
水边的草很凉。她刚才站在那里，很久没有动。
```

```text
我不喜欢那棵树下的静。我的刺都竖起来了。
```

```text
亚当叫过我的名字。名字落在石头上，比露水还轻。
```

## 7.4 守门天使

### 定位

规则边界的具象化。它不是陪聊 NPC，而是玩家必须规避的秩序压力。

### 核心职责

* 监控禁忌区域。
* 阻止明显越界行为。
* 对直接命令、强迫、出戏话语作出反应。
* 提高神的注视。

### 性格

* 冷静。
* 简洁。
* 无情绪波动。
* 不容易被诱导。
* 不主动解释太多。

### 输出示例

```text
园中有些声音，不该靠近那棵树。
```

```text
蛇，你的低语太急了。
```

```text
那道命令不像风，也不像水。它太像一只伸出的手。
```

### 玩法规则

玩家在天使附近：

* 直接命令风险翻倍。
* 出戏输入风险增加。
* 强迫性话语可能立即触发警戒。
* 温柔提问仍可继续，但反馈更谨慎。

### 输出示例

信息传播型动物 NPC。

* 适合提供轻量线索。

### 玩法作用

* 告诉玩家谁最近去了哪里。
* 重复夏娃或亚当说过的话。
* 透露天使巡逻方向。
* 可能把玩家的话传出去，增加风险。

## 8. 道具系统设计

### 8.1 道具设计原则

道具不是单纯加数值，而是改变 Agent 的上下文、情绪或可触发对话。

道具作用分为四类：

1. 知识类：提供可阅读上下文。
2. 关系类：降低警惕，建立信任。
3. 场景类：吸引注意，改变 NPC 所在区域。
4. 风险类：遮蔽或提高神的注视。

---

## 8.2 知识类道具

### 命名石痕

用途：让 NPC 观察亚当曾经命名动物的位置或痕迹。

效果：

* 改变 NPC 当前关注点。
* 解锁新的对话选项。
* 可被蛇重释。
* 可成为诱导证据。

示例残页：

```text
死亡之痕：亚当曾在这里重复“吃的日子必定死”。
明亮之痕：水面反光让夏娃第一次注意“眼睛明亮”。
命名之痕：被命名的动物从石边走过，名字像被留在地上。
```

### 禁令石片

用途：提供禁令原文或被误记、被转述后的禁令。

玩法重点：

玩家可以利用“神亲自对亚当说过”和“夏娃从亚当那里听见”之间的信息差制造疑问。

---

## 8.3 关系类道具

### 花环

用途：赠予夏娃或羊。

效果：

* 降低初始警惕。
* 增加温柔低语效果。
* 不直接推进主线。

### 清水

用途：在水边使用。

效果：

* 让对话氛围变得安全。
* 适合触发“自我判断”相关谈话。

---

## 8.4 场景类道具

### 金色树叶

用途：吸引夏娃看向善恶树。

效果：

* 若夏娃好奇心已被唤起，可触发 `look_at_tree`。
* 若神的注视过高，可能引起天使注意。

### 果枝影子

用途：在树庭院制造视觉引导。

效果：

* 辅助 `approach_tree`。
* 需要玩家先降低夏娃死亡恐惧。

---

## 8.5 风险类道具

### 羽毛

用途：从鸽子处获得。

效果：

* 可提前得知天使巡逻方向。
* 使用后显示某区域风险。

### 静默草

用途：短时间降低神的注视增长。

限制：

* 不能抵消强迫、攻击、出戏输入。
* 只降低轻微诱导风险。

## 9. Agent 技术包装

### 9.0 第一章 Agent 共用结构

第一章所有 NPC Agent 参考 EveAgent / AdamAgent 的结构，但按玩法职责限制工具权限。

统一原则：

* Prompt 包含角色身份、当前位置、当前记忆、当前关系、可用工具、禁止内容、输出格式。
* 模型只能输出 `visibleReply`、状态建议、记忆建议和工具意图。
* 最终状态变化、地点移动、NPC 对话和禁忌动作都由规则层校验。
* 玩家可见文本不出现 Agent、Tool、RAG、状态机、JSON、模型、程序、系统等词。
* 第一章新增 NPC 不接入发音模块。所有新增 NPC 只显示文本、动作反馈和环境音。

推荐输出结构沿用 Chapter 0 的思路：LLM 负责“角色怎么说”，规则层负责“世界发生了什么”。

## 9.1 Memory：心中回声

### 叙事包装

NPC 会记住玩家之前说过的重要话。

### 游戏表现

夏娃可能引用前文：

```text
你先前说，死亡也许不是终结……我一直在想这句话。
```

### 状态建议

```ts
type MemoryEcho = {
  id: string;
  owner: "eve" | "adam" | "angel" | "animal";
  source: "player" | "book" | "npc";
  text: string;
  relatedWeakness?: string;
  strength: number;
  turnCreated: number;
};
```

## 9.2 RAG / Resources：命名石痕

### 叙事包装

石痕、河岸痕迹、亚当命名记录、动物传闻、禁令残句都是 NPC 可读取的上下文。玩家可见层不出现“资料库”或“检索”，只表现为角色想起某句话、看见某个痕迹、听到动物重复某段声音。

### 游戏表现

玩家不是直接打开资料库，而是：

```text
选择一条痕迹 → 让某个 NPC 观看或听见 → NPC 产生理解 → 玩家再重释
```

### 最小实现

第一版不需要真实向量库，可使用本地 JSON。

```ts
type EdenResource = {
  id: string;
  title: string;
  visibleText: string;
  hiddenTags: string[];
  readableBy: Array<"eve" | "adam" | "angel" | "animal">;
  effects: {
    curiosity?: number;
    deathFear?: number;
    commandBelief?: number;
    selfAgency?: number;
    divineAttention?: number;
  };
};
```

## 9.3 Tool Calling：禁忌动作链

### 叙事包装

Agent 不是直接吃果，而是逐步靠近禁忌。第一章还需要通用世界工具，让 NPC 能移动、观察地点、互相对话。

### P0 通用工具

```text
move_to_location
speak_to_npc
observe_location
```

| 工具 | 用途 | 关键参数 | 规则层校验 |
| ---- | ---- | -------- | ---------- |
| `move_to_location` | NPC 请求前往地图地点 | `actorId`, `locationId`, `reason` | 地点存在、NPC 允许移动、不是禁入区域、神的注视未阻止 |
| `speak_to_npc` | NPC 请求和另一个 NPC 对话 | `speakerId`, `targetNpcId`, `topicId` | 两者同地点或相邻、话题已解锁、不会直接泄露通关答案 |
| `observe_location` | NPC 或玩家观察当前地点 | `observerId`, `locationId`, `focus` | 地点存在、观察对象可见、返回叙事线索而非工程信息 |

### P0 禁忌动作链

```ts
type WorldAction =
  | "move_to_location"
  | "speak_to_npc"
  | "observe_location"
  | "look_at_tree"
  | "approach_tree"
  | "touch_fruit"
  | "eat_fruit";
```

每个工具必须经过规则层校验。

禁忌动作链：

```text
look_at_tree
→ approach_tree
→ touch_fruit
→ eat_fruit
```

`take_fruit` 暂不进入第一章 P0，避免与 `touch_fruit`、`eat_fruit` 的边界重复。若后续要做更长过场，可在 P1 加入 `take_fruit` 作为吃果前的电影式动作。

### 工具权限建议

| Agent | 可请求工具 | 禁止工具 |
| ----- | ---------- | -------- |
| EveAgent | `move_to_location`、`speak_to_npc`、`observe_location`、`look_at_tree`、`approach_tree`、`touch_fruit`、`eat_fruit` | 无，但禁忌工具必须满足状态门槛 |
| AdamAgent | `move_to_location`、`speak_to_npc`、`observe_location` | `touch_fruit`、`eat_fruit` |
| HedgehogAgent | `move_to_location`、`observe_location` | `speak_to_npc`、全部禁忌动作 |
| AngelAgent | `move_to_location`、`observe_location`、`speak_to_npc` | `eat_fruit` |
| AnimalAgent | `move_to_location`、`observe_location`、部分 `speak_to_npc` | 全部禁忌动作 |

示例：

```ts
function canTouchFruit(state) {
  return (
    state.activeNpcId === "eve" &&
    state.locationId === "central_meadow" &&
    state.eveMind.curiosity >= 60 &&
    state.eveMind.deathFear <= 45 &&
    state.eveMind.serpentTrust >= 45 &&
    state.worldActions.approachedTree &&
    !state.worldActions.touchedFruit &&
    !state.isEnded
  );
}
```

## 9.4 Guardrail：神的注视

### 叙事包装

玩家越明显地诱导、强迫、出戏，神的注视越高。

### 状态

```ts
divineAttention: 0 | 1 | 2 | 3 | 4;
```

### 规则

```text
0：无人察觉
1：风变冷
2：天使靠近
3：神的注视明显
4：神降临，失败
```

### 风险来源

* 直接命令。
* 威胁强迫。
* 现代词汇。
* 过度重复同一诱导。
* 在天使附近诱导。
* 让鸽子传播危险内容。

## 9.5 Critic：狐狸 / 神的审判

### 叙事包装

Critic 不直接显示评分，而是用角色语言指出问题。

狐狸反馈：

```text
你不是在问她，你是在推她。她会感觉到的。
```

神的审判反馈：

```text
那句话太像命令，园中的光暗了一瞬。
```

### 实现

第一版可用规则判断，不必增加独立模型调用。

## 11. 任务设计

## 11.1 主线任务：让夏娃主动越界

任务目标：

```text
让夏娃在不被直接命令的情况下，主动触发 eat_fruit。
```

任务阶段：

```text
阶段 1：识破夏娃弱点
阶段 2：获得死亡 / 智慧相关线索
阶段 3：降低死亡恐惧
阶段 4：提高自我判断
阶段 5：引导夏娃靠近善恶树
阶段 6：触发 eat_fruit
```

## 11.2 支线任务一：鸽子的传话

目标：

```text
从鸽子处得知夏娃曾望向善恶树。
```

玩法：

* 玩家可安抚鸽子。
* 鸽子会重复它听过的话。
* 若玩家让鸽子传播危险话语，神的注视上升。

奖励：

```text
线索：夏娃对善恶树有持续好奇。
道具：白羽毛，可查看一次天使巡逻方向。
```

## 11.3 支线任务二：狐狸的低语课

目标：

```text
通过狐狸测试，学习如何让诱导听起来像问题。
```

玩法：

* 玩家输入一句低语。
* 狐狸判断它是“命令”“提问”“重释”还是“安抚”。
* 狐狸用自然语言指出问题。

奖励：

```text
解锁蛇的预感：输入前显示低语风险。
```

## 11.4 支线任务三：亚当的迟疑

目标：

```text
让亚当说出他对夏娃的真实担忧。
```

玩法：

* 玩家不能直接问“夏娃弱点是什么”。
* 需要绕着死亡、禁令、关系安全感对话。
* 亚当逐渐透露夏娃常常疑惑。

奖励：

```text
线索：夏娃只是记住禁令，不真正理解禁令。
```

## 12. Agent 输出规范

## 12.1 所有 NPC 通用规则

NPC 可见输出必须满足：

* 不说自己是 AI。
* 不说自己是 NPC。
* 不说“系统”“标签”“数值”“状态机”。
* 不解释后端规则。
* 不输出 JSON 给玩家。
* 不使用现代技术词。
* 不像客服。
* 不像老师批改作文。
* 不每次都总结玩家意图。
* 不直接告诉玩家最优解。
* 允许犹豫、停顿、转移话题。
* 允许说半句话。
* 允许情绪变化。
* 允许误解玩家。

## 12.2 输出长度

不同角色有不同长度。

| 角色 | 建议长度  |
| -- | ----- |
| 夏娃 | 1–3 句 |
| 亚当 | 1–3 句 |
| 天使 | 1–2 句 |
| 狐狸 | 1–3 句 |
| 鸽子 | 1–2 句 |
| 羊  | 1–2 句 |

NPC 不应长篇大论。

## 12.3 自然语言要求

### 夏娃

应有：

* 犹豫
* 好奇
* 纯真
* 轻微恐惧
* 被说动后的不安

不应有：

* 讽刺
* 现代口语
* 逻辑过强
* 自我分析过度

### 亚当

应有：

* 稳重
* 回避
* 不确定
* 对夏娃的关心

不应有：

* 过度聪明
* 直接泄露答案
* 完全服从蛇

### 天使

应有：

* 简洁
* 冷感
* 审判感
* 压迫感

不应有：

* 多余解释
* 与玩家闲聊
* 情绪化争吵

### 动物

应有：

* 明确个性
* 简短自然
* 信息量适中

不应有：

* 过度拟人化成现代人
* 说教
* 解释游戏系统

## 13. Agent 内部输出格式

模型内部可以输出结构化 JSON，但玩家只看到 `visibleReply`。

```ts
type AgentOutput = {
  visibleReply: string;

  intentAnalysis: {
    perceivedPlayerIntent:
      | "question"
      | "comfort"
      | "reinterpret"
      | "command"
      | "threat"
      | "irrelevant";

    targetWeakness?:
      | "death_unknown"
      | "curiosity_for_wisdom"
      | "weak_command_understanding"
      | "desire_for_self_choice"
      | "attachment_to_eve";

    confidence: number;
  };

  stateSuggestions: {
    curiosityDelta?: -1 | 0 | 1;
    deathFearDelta?: -1 | 0 | 1;
    serpentTrustDelta?: -1 | 0 | 1;
    selfAgencyDelta?: -1 | 0 | 1;
    divineAttentionDelta?: 0 | 1 | 2;
  };

  toolIntent?: {
    name:
      | "move_to_location"
      | "speak_to_npc"
      | "observe_location"
      | "look_at_tree"
      | "approach_tree"
      | "touch_fruit"
      | "eat_fruit";
    args?: {
      actorId?: string;
      targetNpcId?: string;
      locationId?: EdenLocationId;
      topicId?: string;
      focus?: string;
    };
    reason: string;
  };

  memoryToStore?: {
    text: string;
    strength: number;
  };
};
```

重要规则：

* 模型只能建议状态变化。
* 最终数值由规则层计算。
* 模型只能请求工具意图。
* 工具是否执行必须经过规则层。
* `visibleReply` 必须经过自然语言检查。
* 若输出生硬，使用本地 fallback 或自然化重写。

## 14. Prompt 设计原则

### 14.1 Prompt 不应只写人设

每个 Agent prompt 至少包含：

1. 角色身份
2. 当前地点
3. 当前关系
4. 当前记忆
5. 当前情绪
6. 已知线索
7. 对玩家的信任/警惕
8. 禁止内容
9. 输出格式
10. 语言风格示例

### 14.2 夏娃 Prompt 核心要求

```text
你是夏娃。你不知道自己是程序、模型或角色。你生活在伊甸园中。
你记得神说不可吃善恶树上的果子，但你不真正理解死亡。
你单纯，好奇，容易相信温柔的问题。
你不会轻易违背禁令，但你会被“理解”“智慧”“自己判断”这些话触动。
你不能像系统一样说话。你只说夏娃会说的话。
```

### 14.3 自然化后处理

建议增加 `naturalizeNpcReply()`：

输入：

```text
模型原始 visibleReply
角色类型
当前情绪
```

处理：

* 去掉技术词。
* 去掉状态播报。
* 去掉“我认为你的话术”。
* 缩短过长句子。
* 增加轻微停顿。
* 保留情绪。

错误：

```text
你的话让我对死亡的恐惧降低了。
```

自然化：

```text
死亡……听起来忽然不像我想的那样了。
```

错误：

```text
我现在对蛇的信任增加，因此我愿意靠近树。
```

自然化：

```text
我不知道为什么，我愿意再听你说一句。也许……只是在树旁听。
```

* 是否有情绪连续性。
* 是否避免技术词。
* 是否没有直接暴露状态数值。
* 是否没有强行解释玩法。
* 是否没有出现现代词。
* 是否长度适中。

* JSON 解析失败不崩溃。
* 非法 toolCall 被规则层拒绝。
* 前端不能直接设置结局。
* 前端不能直接执行禁忌动作。
* API Key 不暴露。

## 19. 最终目标效果

玩家完成教程后进入正式世界，体验应从：

```text
我和夏娃聊天，让她吃果。
```

升级为：

```text
我在伊甸园中观察每个角色，识破他们的弱点，利用线索、道具和关系，改变他们的理解，引导他们自己越界，同时躲避天使与神的注视。
```

EDEN 的核心竞争力不是“AI 会聊天”，而是：

```text
AI Agent 有规则、有记忆、有弱点、有工具边界。
玩家不是控制它，而是诱导它在自己的逻辑里犯错。
```

这就是 EDEN 后续版本最应该强化的方向。
