## 三、发现的风险与问题

### 3.1【中】`eden-attention-cluster` 用 `<span>` 包裹 `<div>`，HTML 嵌套非法
- **位置**：`DivineAttentionViz.tsx:59`(`<span className="eden-attention-cluster">`) 内含 `:73`(`<div className="eden-attention-progress">`)。
- **影响**：`<span>` 是行内元素，`<div>` 是块级。Next.js SSR 生成的 HTML 字符串被浏览器解析时会隐式闭合 span，导致 div 逃逸为 span 的兄弟节点而非子节点 → `eden-attention-cluster` 的 `display:flex` 不再作用于进度条 div → 水滴与进度条可能无法对齐（恰是问题 2 要修复的目标）。客户端 hydration 时 React 虚拟 DOM 与实际 DOM 不一致，可能产生 hydration 警告并重新渲染。
- **建议**：将 `eden-attention-cluster` 的 `<span>` 改为 `<div>`（其在 `eden-header-left` flex 容器内，div 不影响布局）。
- **验证**：浏览器控制台查 hydration 警告；视觉确认水滴/进度条/文字三者同基线对齐。

### 3.2【中】问题 4 根因未明确锁定，"柔化"可能未消除矩形
- **位置**：`globals.css:612/619/782`。
- **现状**：开发降低了 `.eden-stage::before`/`::after`、`.eden-grass-foreground` 的 alpha 与高度，但规划要求"先用 DevTools 定位具体矩形元素"。
- **风险**：若实际矩形是其他元素（如某角色容器残留 `background`/`box-shadow`、或 `.eden-bg-overlay--browse` 的某层），仅柔化 stage 伪元素与草叶不能消除矩形，只会让它变浅。测试者原反馈是"较浅但明显的黑色矩形"——变浅不等于消失。
- **建议**：运行时用 DevTools 元素检查器在 `/world` 浏览态选中该矩形，确认选择器后再针对性移除；不要仅靠降 alpha 收尾。
- **验证**：浏览多个地点（尤其 central_meadow、adam_garden_work）确认无任何矩形暗块。

### 3.3【低】aweReduction 反馈置于对话 Tab 内，与"面板精简"目标略有张力
- **位置**：`page.tsx:1121-1124` 把敬畏扣除反馈拼入 `npcFb` → `npcFeedbackState`（渲染在对话 Tab 内）。
- **规划原意**：可选建议是"对话区外提示"。
- **判定**：可接受偏差（反馈与本次低语直接相关，放对话区有合理性），但若严格遵循"对话 Tab 只显示角色发言与必要叙事"，更宜用独立浮动提示。非阻塞。

### 3.4【低】死参数 / 死代码
- `stageSlots.ts:32` `allocateStageSlots` 仍接受 `activeNpc` 参数但已不用于排序（死参数）。
- `route.ts:788-789` else 分支内仍引用 `move_one_step` 计算 `fromLocationId/toLocationId`（该分支不可能命中 move_one_step，死代码）。
- **影响**：无害，建议清理以降维护噪音。

### 3.5【低】lint 2 条 useCallback 依赖告警未消除
- 开发说明 exit 0（非错误）。建议补全依赖或加 eslint-disable 注释说明，避免后续被误判为新问题。
