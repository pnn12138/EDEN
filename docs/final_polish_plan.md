## 逐条分析

### P0-1：统一对外版本口径

**分析：核心任务，必须先做。** 当前首页两个入口 + README 只写旧版，评委打开后会困惑。

**执行方案（约 30 分钟）：**

1. **首页改为单入口**：移除 E-00 按钮，只保留「进入伊甸园」→ `/world`
2. **README 重写**：改为描述当前第一章"园中诸声"的探索玩法
3. **旧文档归档**：在 `doc/DEMO_VIDEO_SCRIPT.md` 顶部加 `[已归档 - Chapter 0 旧版]` 标记

### P0-2：锁定可重复完成的主线

**分析：已验证可完成，但需要做可靠性测试。** 已在 demo route test 中证明 5 时段可达结局。

**执行方案（约 20 分钟）：**

1. 连跑 3 次 `LLM_PROVIDER=mock node scripts/test-demo-route.mjs`，确认每次都到结局
2. 检查刷新/重复点击场景互动是否有边界问题
3. **关键发现：当前场景互动每次点击消耗 1 AP。刻名石 3 击 = 3 AP，加上移动 = 5 AP 耗光。这在实际游玩中会让玩家困惑** —— 这是 P0-3 的问题。

### P0-3：点击-获得-使用-推进 反馈清晰度

**分析：这是当前最大的体验问题。** 测试发现：

- 刻名石 3 次点击，每次消耗 1 AP，每次调用 scene_action API，前两次只有进度反馈，第三次才有道具
- 刺猬 3 次点击同样问题
- AP 消耗在"点击计数"上而非"完成互动"上，玩家会觉得被惩罚

**执行方案（约 40 分钟）：**
- 前端不应该每次点击都调 API。改为：前端累积点击次数，只在最后一步调 API 消耗 1 AP
- 或者：降低所有场景互动的点击次数到 2 次（已完成），但每次调 API 仍消耗 1 AP 的问题需要前端改动

**务实方案（不增加新代码）：** 当前前端每次点击都调 API 是架构决定的，改起来涉及前后端。**折中：将 AP 从 5 提升到 8**，让玩家有足够余量探索。或者**将场景互动从 3 次改为 2 次，刻名石从 3 次改为 2 次，刺猬从 3 次改为 2 次**，这样 4 次互动只需 4 AP + 移动 2 AP = 6 AP。但这与之前的"精简"冲突。

**最简方案：保持现状，在视频中通过后期剪辑隐藏 AP 消耗过程。**
